# 与原版相比的改动（CHANGES）

“原版”指重新设计之前的源码快照（提交 `5ad7f22`，“Original source snapshot”）；“现在”指分支 `integ` 的代码（本次更新时为 `5040d0b`）。本文按画面逐一说明改了什么，最后列出删除的内容。**2026-10-12 第二轮按 Kelvin 当天的决定做的改动，按画面单独列在 §7**，§2–§4 里的“现在”已经包含这些改动。设计依据是 `docs/DESIGN.md`，技术约定是 `docs/ARCHITECTURE.md`；谱面格式见 `docs/CHART_FORMAT.md`，资源槽位见 `docs/ASSET_SLOTS.md`；每个模块和类在代码里的位置见开发人员手册 `docs/DEVELOPER.md`。

## 1. 总体

| 方面 | 原版 | 现在 |
|---|---|---|
| 流程 | 欢迎 → （每次）教程 → 选歌列表 → 游戏 → 结算 → 选歌列表 | 欢迎 → 第一次启动时：首次设置 → 教程；之后直接进入潜水地图。地图 → 游戏 → 结算 → 地图。设置、玩家档案、校准从欢迎画面和地图进入 |
| 画面适配 | 1920 × 1080 直接拉伸到屏幕（非 16:9 屏幕会变形） | 菜单等画面不拉伸：16:9、20:9、16:10、3:2、4:3 各有布局，避开刘海和圆角；界面缩放和额外边距可在设置里调整。游戏场地（2026-10-12 起）按屏幕比例拉伸铺满屏幕，但只拉伸位置：音符厚度、文字和四角的 HUD 不变形（§7） |
| 视觉风格 | 静态背景图 + 少量粒子 | 深海下潜主题：程序绘制的海水背景随深度变色，光柱、雪花、声呐波纹；故障风文字；四种转场（DIVE 下潜、ASCENT 上升、IRIS 光圈、CURTAIN 幕布）；提示条（toast） |
| 字体 | Mokoto Glitch 系列、Rubik Glitch | 保留这两种，新增 Chakra Petch（界面文字）和 Noto Sans SC（中文） |
| 存档 | `KandKGame/user.json`：按歌名记录最高分和最近成绩 | 多个本地账号（“潜水员”，最多 8 个），每人有成绩、经验等级、评分和深度、个人设置；设备设置单独保存。存档写入是原子的，带备份和损坏恢复。旧的 `user.json` 在第一次启动时自动导入 |
| 音乐播放 | 只支持 WAV（自带的 WAV 播放器） | libGDX `Music`，支持 ogg / mp3 / wav；歌曲时钟以音频位置为准，支持音频延迟和画面延迟两种校准 |
| 桌面窗口 | 640 × 480 | 1280 × 720，可调整大小（最小 960 × 540） |
| Android | 固定横屏 | 横屏，可随设备方向翻转 180°；加入振动权限用于触感反馈 |

## 2. 逐个画面

### 2.1 欢迎画面

* **原版**：`welcome.png` 铺满屏幕；0.5 s 起淡入标题 “K and K”；3.5 s 后出现 “tap anywhere to DESCEND”，这之前点击无效；点击后**每次都进入教程**。
* **现在**：
  * 开场动画：两颗光点沿螺旋落下、相撞，发出声呐波纹，`K & K` 标志解码出现，随后出现标语和随心跳呼吸的 `TAP TO DESCEND`。2026-10-12 22:04 起不再显示 `welcome.png`，只留海水背景和水纹（文件仍在，以后可以再接上）。
  * 0.3 s 后即可点击；1.2 s 前点击会快进到最终状态，之后点击开始下潜。
  * 可以互动：拖动留下波纹和气泡，两个 K 跟着手指倾斜，点 K 会发出声呐。
  * 左下角是当前潜水员（名字、等级、深度），点开可切换账号；右下角是设置；底部中间显示版本号。
  * 第一次启动进入首次设置；之后进入地图，背景无缝地下潜到地图的深度。返回键退出游戏。

### 2.2 首次设置（新增）

三步，顶部有进度点：

1. **WHO'S DIVING?**：设置头像（可随机重抽、选配色）和名字。如果发现旧存档，会提示成绩将导入这个潜水员。
2. **COMFORT**：故障效果强度（带实时示例）、减少动态、减少闪烁，以及光敏提示。
3. **TUNE YOUR SONAR**：选择音频输出（扬声器 / 有线 / 蓝牙），可以直接进入校准，也可以跳过（跳过后地图会提醒校准）。

完成后进入教程。

### 2.3 选歌：歌曲列表 → 潜水地图

* **原版**：左侧滚动歌曲列表；右上难度面板（SURFACE / SHALLOW / DEEP / ABYSS），右下排序面板（按标题 / 难度 / 分数，升序或降序）和 AUTOPLAY 开关；中间是曲绘和 DESCEND 按钮；左上问号按钮进入教程。背景是 `Blue.png` 加粒子，播放 `background.wav`。
* **现在**：选歌变成一张可以自由拖动的“潜水海图”：
  * 每个章节是一个深度层（浅滩 0–200 m、暮光层 200–1000 m、午夜层 1000–4000 m，以及两个“未探明”层），每首歌是潜水路线上的一个浮标节点。章节和歌曲由 `assets/Charts/index.json` 决定。
  * 拖动有惯性，两指或滚轮缩放，双击缩放。HUD 上有深度计（可拖动快速跳转）、回到当前位置按钮、“镜头”难度切换（决定节点和卡片显示哪个难度）和当前层名称。
  * 点节点：节点弹起，镜头滑过去，打开**歌曲卡片**（宽屏在右侧，窄屏从底部弹出），菜单音乐压低，停留 450 ms 后开始试听。长按节点显示各难度最高分。
  * 歌曲卡片：可左右切换歌曲；曲绘；成绩区（最高分、评级、通关标记、准确率、评分、在 TOP 10 中的位置、游玩次数、最近成绩走势和下一个小目标）；歌名、曲师和其他信息；四个难度的定数按钮（可左右滑动切换）；AUTO 开关和 DESCEND 按钮。
  * DESCEND：镜头钻进节点、背景下潜到游戏深度，然后进入游戏（谱面在动画期间就开始加载）。
  * 筛选面板：状态（全部 / 新歌 / 未通关 / 没有 FULL COMBO / 低于 S）、定数范围（1.0–17.0）、按歌名或曲师搜索；不匹配的节点变暗。还有一个列表模式，作为无障碍和快速访问的备用。
  * 右上角有教程和设置按钮，左上角是潜水员徽章（进入玩家档案）。
  * 从游戏或结算返回时，镜头从刚玩的节点退回原位，新玩过的路线被点亮，打破纪录时显示 `NEW BEST`，卡片重新打开。
  * 镜头位置、镜头难度和选中的歌曲保存在每个潜水员的存档里。

### 2.4 游戏画面

* **原版**：画面拉伸到屏幕；3 s 倒计时；左上角三个图片按钮（返回、重来、暂停），暂停时画面变暗；顶部进度条（自动播放时可拖动跳转）；连击数（自动播放时显示 AUTO）；按判定播放 Deep / Shallow 两套粒子。
* **现在**：
  * **谱面模型 v2**：轨道数量不限、宽度可以随时间变化（窗口按权重分配）；新增 MINE 水雷和 TIDE 潮汐两种音符，TIDE 也可以是按住的 TIDE STREAM 潮汐水流，水雷也可以是封住一条轨道的 LANE MINE 轨道水雷；音符可以拖出残影（`trail`，只是光影，不判定）；长条的尾巴可以用 `HeightEvents` 控制长短（纯视觉）；音符名称改为 DROP 水滴、STREAM 水流、MINE 水雷、TIDE 潮汐、TIDE STREAM 潮汐水流、LANE MINE 轨道水雷。原版谱面（v1）不用改，加载时自动转换。见 `docs/CHART_FORMAT.md`。
  * **判定**：三级判定 RESONANCE / ECHO / LOST（见 §3）。判定使用触摸事件自己的时间戳，不受帧率影响；判定区内的触摸一定会被判定；一次触摸最多判定一个目标（例外：打中 DROP / STREAM 时，同一条线同一拍的 TIDE 一起判定）；靠近轨道边界的触摸可以判给相邻轨道。hold 的松手规则更宽容（结尾前 133 ms 内松手算完成，短暂滑出 100 ms 内不算断）；STREAM 要同一根手指按到结束，TIDE STREAM 只要这条判定线上一直有手指，可以换手指。
  * **修复看不见的音符**：原版谱面里有些音符的运动事件没有把音符带到线上，会在看不见的情况下被判定。现在这类音符自动改用标准的 2 拍接近动画。2026-10-12 21:09 起有例外：完全没有运动事件、`appearance` 等于判定拍的音符保持原版的样子（tap 不画出来，长条在判定时直接出现在线上），见 §7.12。
  * **同一位置的重复音符**在加载时去重（原版会叠在一起）。
  * **HUD**（2026-10-12 起放在四角，见 §7.1）：左上分数和准确率，右上暂停按钮，左下难度和歌名，右下剩余时间，顶部细进度条；连击、判定文字和误差条在中间。HUD 最后绘制，盖在音符上面，只显示不拦截触摸。分数（9 位）变化有缓动，PERFECT 时判定字下面闪过一道光，连击每 100 有特效、断连有红色故障闪烁。判定线移动到某个角附近时，那个角自动变淡。
  * **暂停**（2026-10-12 起，见 §7.2）：默认**双击**右上角的暂停按钮（300 ms 内按两下），也可以在设置里改为按住 0.35 s 或单击。所有触摸先交给游戏判定，打到音符、接回 hold、按着进行中的 TIDE STREAM 或碰到水雷的那一下不算暂停的一下。返回键、Esc、键盘的 Pause 键和切到后台立即暂停。恢复时有 3-2-1 倒计时，期间音符静止、不判定。
  * **暂停菜单**（新增；2026-10-12 起是方案 B，见 §7.3）：没有面板，画面变暗，中间一排三个大按钮 RETRY 重开 / RESUME 继续 / QUIT 退出，四角的 HUD 保持亮着。延迟和音量在设置里调；原来菜单下方的音符图例去掉了，将来放在设置的 NOTE GUIDE 音符图鉴里（§2.8）。
  * **反馈**：判定线和轨道发光，触摸位置的波纹，接近提示光，打击特效（RESONANCE、ECHO、hold 光流、LOST ×），DROP / STREAM 的水波纹（2026-10-12 起），碰到水雷的冲击环和红色 `LOST`，TIDE 的潮水（一条柔和的光带从判定线浮起、散开，水退回时短暂变暗；按住 TIDE STREAM 时保持一层低潮位，细光带不断浮起）。每种效果都用判定的颜色（ECHO 是紫色）。打击特效有高 / 低 / 关三档画质，掉帧时自动从高降到低（结算时提示一次）。详见 §7.4、§7.5。
  * **背景**：随章节和难度变化的海水深度；曲绘做成的淡色底；`bg.png`（没有时用 `ChartVisualizer.png`）。
  * **打击音效**：预留了 `Sounds/hit.*` 等槽位，在触摸处理中立即播放（目前不附带文件）。
  * 开场（2026-10-12 16:06 起）：3-2-1 倒计时每个数字 1 s，然后 0.3 s 只有场地、什么都不发生，这 3.3 s 里歌曲时钟不走、音符不出现；之后游戏开始，音符从屏幕边缘出现、开始下落，歌曲时间 0 时音乐开始。不再有开场卡片，也不再闪出 DIVE 字样。在任何屏幕上，转了角度、一出生就会露出一角的音符从屏幕边缘滑进来，不会在画面里凭空出现。歌曲结束时音乐淡出，显示 CLEAR / FULL COMBO / ALL RESONANCE 横幅后进入结算。
  * **场地拉伸**（2026-10-12 16:17 起）：谱面坐标按 1920 × 1080 写；在 a × b 的屏幕上，以屏幕中心为原点，横向乘 a / 1920、纵向乘 b / 1080。判定线、轨道（轨道间距一起变宽，例如 2400 × 1080 上 80 变成 100）、音符下落的距离和尾巴、判定区（19:09 起 ±432 × 纵向比例，见 §7.11）都跟着拉伸，音符仍在判定时刻落到线上；16:9 上和以前完全一样。音符厚度、珠子、波纹、光晕、文字和四角的 HUD 不拉伸，旋转角度不变。教程里跟判定线和轨道有关的说明文字位置也跟着拉伸，文字大小不变。
  * 键盘键位与原版相同，另外空格键用于下线的 TIDE。P 是上排的一个轨道键，不是暂停键。

### 2.5 教程

* **原版**：每次从欢迎画面进入；在游戏画面上叠加按拍出现的说明文字。
* **现在**：只在第一次启动时自动进入，之后可以从地图或设置里重玩。2026-10-12 起是第三版（见 §7.6）：保留原来的故事、悼词和对话，先介绍四角的 HUD、各级判定和 EARLY / LATE、两条判定线，然后每种基本机制一课（DROP、STREAM、金色同步方块、TIDE、TIDE + DROP 联合判定、TIDE STREAM、MINE、LANE MINE、残影、移动的音符），字幕有英文和中文（跟随语言设置）。可以按住 SKIP 0.6 s 跳过：第一次游玩时 10 s 后出现，重玩时一直显示。教程不记录成绩，只发放第一次的经验。

### 2.6 结算画面（DIVE LOG）

* **原版**：`ResultPage.png` 背景；歌名、“难度 Lv.定数”；8 位分数和与最高分的差；MAX COMBO / DEEP / SHALLOW / SURFACE / MISS 五个数字；BACK 和 RETRY 按钮。
* **现在**：按时间线依次出现：曲绘、歌名解码、9 位分数滚动（点分数可看计分明细）、各判定数量（RESONANCE（下面另计 PERFECT）/ ECHO / LOST，以及 EARLY / LATE、碰到的水雷数、RESONANCE CHAIN（共鸣连击）、MAX COMBO、准确率）、判定时间分布图（ECHO TRACE）、评级印章（PURE、S+、S、A+、A、B、C、D）、CLEAR / FULL COMBO / ALL RESONANCE 标记、最高分对比（NEW BEST / FIRST DIVE）、潜水员条（深度和经验的增长，升级和升阶的演出）。点击可以快进。之后还能互动：重新盖章、倾斜曲绘、展开分布图、查看经验明细；判定整体偏早或偏晚时会建议调整音频延迟，并可以直接进入校准。按钮：RETRY（教程为 REPLAY）和 CONTINUE（回到地图）。自动播放的成绩不记录。新增结算音乐槽位（见 `docs/ASSET_SLOTS.md`）。

### 2.7 玩家档案（新增）

左侧是头像（点击编辑）、名字（点击改名）、等级和经验、深度和评分、段位徽章和下一段位；右侧是四个标签页：STATS（统计）、TOP 10（评分最高的 10 张谱面）、LOG（最近记录）、DIVERS（账号管理）。账号可以新建、改名、切换、删除（按住 1.5 s，不能删除最后一个），以及导出 / 导入备份码。

### 2.8 设置（新增）

六个分类：

* **AUDIO**：音乐音量、打击音量、打击音模式、试听开关、菜单音乐开关。
* **TIMING**：音频输出、音频延迟、进入校准、画面延迟、EARLY / LATE 显示、毫秒显示、判定误差条。
* **VISUAL**：故障强度、减少闪烁、减少动态、粒子画质、背景细节、背景图开关、背景图透明度、背景变暗、音符大小、判定区提示、接近光、误触点显示、界面缩放、额外边距、FPS 显示。
* **GAMEPLAY**：暂停方式（2026-10-12 起默认双击）、判定文字位置、实时计数、触感反馈、语言（英文，或加中文副标题）。最后是一块只读的 **NOTE GUIDE 音符图鉴**：六种音符的小图、名字和玩法（2026-10-12 新加，见 §7.7）。
* **ACCOUNT**：备份码、重玩教程、重置教程标记、重置成绩。
* **ABOUT**：版本、制作人员、授权。

标有 DEVICE 的设置保存在本机（例如音量、延迟、画质），其余跟随潜水员。所有修改立即生效。VISUAL 和 TIMING 页有实时预览。

### 2.9 校准（新增）

* **音频延迟**：播放 120 BPM 的节拍声（4 拍预备 + 24 拍测量），玩家跟着点。结果取“点击时间 − 节拍时间”的中位数；点得太散或次数不够会要求重试。可以把结果应用到当前的音频输出（扬声器、有线、蓝牙各存一份），然后用 16 个音符验证。
* **画面延迟**：每个节拍闪一个圆环，用 ±5 ms 调整到闪光和声音对齐。正值表示音符提前到达。

## 3. 判定与计分对照

| | 原版 | 现在 |
|---|---|---|
| 判定等级 | DEEP（≤ 150 ms，得 1 分）、SHALLOW（≤ 175 ms，0.5 分）、SURFACE（≤ 200 ms，0 分）、MISS | RESONANCE（≤ 66.67 ms，权重 1）、ECHO（≤ 133.33 ms，权重 0.55）、LOST；RESONANCE 中 \|Δt\| ≤ 33.33 ms（1000/30）的另计为 PERFECT（不是第四种判定） |
| 分数 | 平均得分 × 10,000,000 | `100,000,000 × (r + 0.55 × e) / t + 10,000 × m_r / t + r_p`（2026-10-14 起，见 §7.31）：r / e = RESONANCE / ECHO 数，t = 音符总数，m_r = 最长连续 RESONANCE（共鸣链），r_p = PERFECT 数；全部 PERFECT 为 100,010,000 + t |
| 音符总数 | 全部音符 | tap + hold + universal（每个 TIDE STREAM 算 1 个，联合判定的每个 TIDE 各算 1 个）；水雷和 LANE MINE 不计 |
| 水雷 | 无 | 在水雷时刻 ±66.67 ms 内碰到（LANE MINE：到线后的封锁期间每次接触）时连击归 0，共鸣链和分数不变，显示红色 `LOST`。碰到任何一个水雷就没有 FULL COMBO 和 ALL RESONANCE，碰在第一个音符之前或最后一个音符之后也一样 |
| 通关标记 | 无 | CLEAR（打完就算，没有失败）；FULL COMBO = 没有 LOST，并且整局没有碰到水雷；ALL RESONANCE = 全部 RESONANCE 且 FULL COMBO |
| 评级 | 无 | PURE（全部 RESONANCE）、S+（≥ 96,000,000）、S（≥ 93,000,000）、A+（≥ 90,000,000）、A（≥ 87,000,000）、B（≥ 82,000,000）、C（≥ 70,000,000）、D；PERFECT 加分不提升评级 |
| 成长 | 无 | 谱面评分 → 潜水员评分（最好 10 张的平均）→ 深度（米）和段位；每局获得经验，等级上限 99 |

### 7.4 音符和判定

* **LANE MINE 轨道水雷**（新音符）：带 `duration` 的 `mine`。从判定前 100 ms 到结束，封住这条线上的这一条轨道，画成一根暗红色的危险柱。封锁期间手指进入这条轨道（中间 80 % 的宽度）或按着这条轨道的键，就像碰到水雷：连击归 0，显示红色 `LOST`。每次进入都算一次，一直停在里面不重复算。它碰到判定线后就不再移动（「轨道水雷没法上下移动。碰到判定线就不能再动了」）；穿过另一条判定线时留出一道缝，那条线照样看得清。结算的 MINES 一行里，一个 LANE MINE 只算一个水雷。
* **水雷的危险窗口**从 ±66.67 ms 放宽到 **±100 ms**（「地雷按的范围是+-100ms」）。2026-10-13 又改回 ±66.67 ms，轨道水雷改成到线才封锁，见 §7.27。
* **碰到水雷显示红色 `LOST`**（比普通 LOST 更红），包括每次接触 LANE MINE。它只是提示：不记判定，不加误差条的刻度。同一次触摸既碰到水雷、又打中了一个音符时（例如在发红的 LANE MINE 轨道里点一下，同时打中这条线的 TIDE），中间的字保持红色 `LOST`，说明连击为什么断了；那个音符照常判定，误差条照常加一格，下一个判定照常替换这个字。
* **水雷会转**：MINE 和 LANE MINE 像 DROP / STREAM 一样按 `RotationEvents` 旋转，残影也跟着转。
* **联合判定**：同一条线、同一拍上的 DROP / STREAM 和 TIDE，打中 DROP / STREAM 的那一下同时判定 TIDE（同样的判定和误差，各算一个音符）。没打中 DROP / STREAM 的触摸只判定 TIDE。取代了以前“先判轨道音符，TIDE 留给另一根手指”的规则。
* **同步提示改成金色小方块**（「sync的就在中间的部分加一个金色的正方形。其他的都不变」）：需要第二根手指的 DROP / STREAM，头部正中画一个金色方块，其他不变。取代了原来的金色描边和连线。只和同一条线的 TIDE 同拍的 DROP 没有方块，因为联合判定一下就打完了。
* **TIDE 的新外形**：天空线是一串珍珠，地面线是一道滚动的浪。TIDE 先画，DROP 和水雷画在它上面，不会被浪盖住。
* **长条可以越拉越长**：新的 `HeightEvents` 控制 STREAM、TIDE STREAM、LANE MINE 尾巴的长度（只是画面，不影响判定），见 `docs/CHART_FORMAT.md` §4.1。
* **上下两条线的音符重叠时**：天空线的 STREAM 水流宽 56 %（地面线 82 %），从头到尾逐渐变淡，尾部有自己颜色的收口；重叠处地面线的水流让出天空线水流的宽度。这一版先保留（「长条改的也很自然，先保留吧我再看看」）。天空线的 TIDE 用珍珠色（`skyTide`）。

### 7.5 打击反馈

* **水波纹**：DROP / STREAM 打中时，从打中的位置扩散出圆环。RESONANCE 是五个粗的青色圆环，ECHO 是一个细的紫色圆环；按住 STREAM 时，按住的位置每隔一小段时间冒出一个小圆环。
* **每种效果都用判定的颜色**：RESONANCE 青色，ECHO 紫色。TIDE 的效果和水波纹也一样。
* **TIDE 打中的效果（第三版潮水）**：一整条柔和的光带从判定线浮起、散开，被抬起的水退回、淡出，同时短暂变暗；判定线本身微微抬起、发光。ECHO 浮得低一些、淡一些。TIDE 打中时，手指的位置上不再有任何圆环或点状特效。
* **TIDE STREAM 按住时**，细光带按固定节奏从线上浮起，频率和 STREAM 的光点流一样（高画质每秒 22 条，低画质 12 条，关闭时没有）。换手不会打断或重启这个节奏。
* **轨道分隔线**改成贯穿两条判定线之间的全高线，在判定线附近较亮，中间较淡。

### 7.21 无限轨、全局缩放和部分缩放（2026-10-13 04:05–04:27，谱面编辑器串选了「宽度固定」）

* **不写 `laneCount` = 无限轨（默认，旧谱面也是）**：每条轨道保持自己的宽度（默认 240），1 号轨道从 x 960 往右排，−1 号往左排；判定区窗口只决定露出哪些轨道、哪里能判定。默认窗口 0–1920 正好露出 −4..4 共 8 条，窗口变宽就在两边多露出轨道。窗口外的轨道仍然存在，只是不画、不能点。谱面里没写到的轨道 id 自动补默认轨道（最多 ±64，存档时不写出）。

### 7.31 分数公式改版；轻点 PERFECT 看早／晚共鸣（2026-10-14 00:09，Kelvin）

### 7.36 暂停后继续，音乐越来越晚（2026-10-15 13:04，Kelvin）

* Kelvin 13:04：「发现新bug：如果暂停之后再resume，音乐和按键就会偏移一点，且这种偏移是不断累加的，最后音乐会比谱面晚。不管是autoplay还是游玩都有这个问题」
* 原因：手机（安卓 MediaPlayer）直接继续播放时，它报告的进度马上往前走，声音却要晚一点才出来，有的手机之后不会把这段时间补回来；时钟跟着报告的进度走，所以每暂停一次谱面就比音乐多领先一点。电脑上（OpenAL）实测连停 8–12 次没有偏移。
* 修复（`SongClock`）：安卓上继续时先把音乐跳到谱面暂停的位置再播放，跳转会让播放器重新按真正出声的位置计时；所有平台继续后时钟停在暂停处，等音乐的进度真正动起来再走（最多等 0.4 秒），谱面不会在音乐出声前抢跑。循环播放的音乐（校准）和已经超过音乐结尾的位置不跳转。
* 测试：harness `ResumeSyncTests`（模拟手机：修前停 10 次谱面领先 1.2 秒，修后 0；电脑式播放器不跳转、不偏移）。
