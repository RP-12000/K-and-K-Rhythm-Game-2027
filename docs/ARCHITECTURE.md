Java 11 source level (`--release 11`: no records, no `var` in lambdas is fine, no switch expressions with `->` yield? — **switch expressions/records/text blocks are NOT allowed**, Java 11 only). libGDX 1.14.1, ShapeDrawer 2.5 API (`space.earlygrey.shapedrawer.ShapeDrawer`; the build pins 2.5.0), Jackson 2.17 **streaming core only** (`jackson-core`; jackson-databind is not used: its bean introspection calls `Method/Constructor.getParameterCount()`, API 26, see §7), FreeType. Android minSdk 21 (Java 8 APIs via desugaring are OK: `java.util.function`, streams OK but avoid in render loops).

**Wave 2 (owner decisions of 2026-10-12, as built on `integ` 5040d0b):** folded into §5, §10, §13, §18–§20 and indexed in §21; superseded text is marked **Replaced**. The copy in the repo (`docs/ARCHITECTURE.md`) is this file.

Visual / UX decisions live in `docs/DESIGN.md`. This file defines **code structure, ownership and APIs**. When DESIGN.md and this file disagree about code structure, this file wins; for looks, DESIGN.md wins.

## 0. Golden rules
1. **No per-frame allocation** in render/update/input paths (no `new` of GlyphLayout/Color/Vector2/String.format/lambdas/iterators over ArrayList in hot loops — use indexed loops, reuse fields, `StringBuilder` + cached digits).
2. **No StretchViewport anywhere.** World = `ExtendViewport(1920, 1080)` (min world 1920×1080, longer axis extends). Camera centred at (960, 540) for gameplay; menus may anchor to visible edges via `Ui`.
3. **GL objects are never static** (Android context loss). They belong to `Main`'s services or to a screen, created once, disposed in `dispose()`.
4. Screens are **created once and cached** by `Main` (except throwaway ones), `show()` must be idempotent (no re-allocation), `hide()` releases input/music only.
5. Screen switches go **only** through `Main.transitionTo(...)` / `Main.switchNow(...)` which defer the actual `setScreen` to the start of the next frame (never inside another screen's render).
6. Fonts are baked **white** and tinted at draw time; never mutate a shared font's color without restoring it — use `Fonts.draw(...)` helpers.
7. Every user-visible string that can contain non-ASCII (player names, song titles) is drawn through `Fonts` which routes to the CJK font automatically.
8. Touch targets ≥ 48 dp (`Ui.dp(48)` in world units). Act on **release (tap)**, never on touchDown, except gameplay note input.
9. Android BACK (`Gdx.input.setCatchKey(Input.Keys.BACK, true)` set once in Main) and desktop ESC map to each screen's "back" action via `Main`'s global key handling → `KkScreen.onBack()`.
10. Keep code idiomatic to the existing style (4-space indent, Javadoc on public classes). Remove dead editor leftovers you touch. No `Gdx.app.log` in hot paths.

## 3. ui package — FOUNDATION
* `Ui` (static helpers, recomputed in `onResize`): `worldW()`, `worldH()`, `left()/right()/bottom()/top()` = visible world edges for a camera centred at (960,540); `safeLeft()/safeRight()/safeTop()/safeBottom()` = edges inset by `Gdx.graphics.getSafeInset*` converted to world units (+ a minimum margin of 24 world units); `pxPerWorld()` (uniform screen pixels per world unit); `dp(float)` = `dp * Gdx.graphics.getDensity() * 160/160 / pxPerWorld()` clamped to a sane range; `aspect()`; `isTablet()` (aspect < 1.6); `isTall()` (aspect > 1.9).

* `Anim`: easing functions (`outCubic`, `outBack`, `outExpo`, `inOutSine`, `outElastic`), `Spring` (critically/under-damped scalar spring with `update(delta)`), `Tween` helpers without allocation.
* `Fonts` (replaces FontSystem):

  Character sets: DISPLAY/RUBIK/UI* = ASCII + Latin-1 + `·•—…–→←↑↓★☆♪×÷±%°`; NUMBER = `0123456789.,:+-%×xX/` + ` `; CJK = incremental (FreeType `incremental = true`, shared packer). Mokoto is unicase; use it for uppercase display text only.
* `GlitchText`: `draw(Batch, Fonts, Role, refPx, text, x, y, align, Color, float intensity, float time)` → draws the clean glyphs plus procedural RGB split (cyan/magenta offset ±(1..3)·intensity world px, jittered by a hash of floor(time*fps)) and occasional horizontal slice offsets (draw text clipped into 2–4 horizontal bands with ScissorStack or by drawing 3 copies with per-band alpha?) — pick a cheap approach: 3 tinted draws (R, G/B split) + rare slice jitter using `BitmapFontCache` translation. Respect `profile.settings.glitchIntensity` (0..1) as a global multiplier.
* `Draw`: owns the shared `SpriteBatch` (1), a `TextureRegion white` from a generated 4×4 white Pixmap (not white_pixel.png static), a `ShapeDrawer`, and a soft radial "glow" texture + "ring" texture generated procedurally (Pixmap) for UI/backdrop/particles. Accessors `batch()`, `shapes()`, `white()`, `glow()`, `ring()`, `noise()` (64×64 tiling noise for shaders).
* `Backdrop`: the shared procedural background (DESIGN.md §2). API:
  ```java
  void setDepth(float depthMeters);      // smoothly animates palette toward the depth (0 = surface)
  void setDepthImmediate(float depthMeters);
  void setImage(Texture tex);            // optional image hook overlay (null = none); drawn cover-fit with DESIGN alpha
  void setIntensity(float motion01);     // gameplay uses lower motion
  void touch(float worldX, float worldY);// ripple / sonar ping at a point (menus call this on taps)

  ```
  Implementation may use one small GLSL ES 2.0 shader (gradient + caustic/light-shaft noise) plus a pooled particle field (marine snow / bubbles) drawn as glow sprites. Must cost < 1.5 ms on mid phones: shader on a full-screen quad at **half resolution** via FrameBuffer is acceptable, or direct with cheap math.
* `Button`: lightweight tappable widget (rect in world units, label, icon draw callback, pressed scale spring, disabled state, `boolean touchDown/touchUp(x,y)`, `Runnable onTap`). Fires on up inside with slop `Ui.dp(12)`.

**As built (integration, binding; the code wins per §14):** `Slot { MENU, PREVIEW, RESULT, HIT }`; MENU is `assets/background.(ogg|mp3|wav)`. `hitSound()` loads and primes (one volume-0 play) all four reserved Sound slots together on first use: `Sounds/hit.*`, `hit_echo.*` (ECHO instead of `hit`), `hold_end.*` (`playHoldEnd()`) and `mine.*` (`playMine()`, called on a touched mine; a mine never plays `hit`), each `<name>.ogg` then `<name>.wav`, volume `sfxVolume`, silent when absent. `playResult(song)`: the song folder's `result.(ogg|mp3|wav)` started at the manifest's `resultMusicStartMs` (the offset applies only to that per-song file), else `assets/Audio/result.(ogg|mp3|wav)`, else the temporary `assets/Introduction/Introduction.wav`, else silence; fades in over `RESULT_FADE_IN` 1.2 s to `musicVolume × RESULT_GAIN` (0.8) and loops. Owner-facing slot docs: `assets/Audio/README.txt`, `assets/Sounds/README.txt`, `docs/ASSET_SLOTS.md`.
`SongClock` (gameplay clock; one instance owned by GameEngine):
```java
void load(FileHandle music);            // creates Music, reads duration (WavDurationUtil for .wav else from metadata/fallback)
void prepare(float startMs);            // lead-in start (negative ms allowed), paused
void start(); void pause(); void resume(); void seek(float ms); void dispose();
void update();                          // once per frame BEFORE input is used? (see below)
double nowMs();                          // smoothed song time at "now" (System.nanoTime()), audio-anchored
double timeAtNanos(long nanos);          // song time at an input event timestamp (Gdx.input.getCurrentEventTime())
long nanoTime();                         // the clock's time-source reading (System.nanoTime unless a test replaced it)
void setTimeSource(SongClock.TimeSource s); // tests only
void attach(Music m, float durationMs, boolean takeOwnership); // attach(null, …) = a silent run (no music)
float durationMs();
```
Behaviour: during lead-in (t<0) time runs from nanoTime; when t crosses 0 the music starts. **With music attached, that crossing anchors song time 0** at the frame the stream starts at position 0, so audio and clock agree from the first frame (`nowMs()` was < 0 the frame before, so time never goes back); a **silent run** (`attach(null, …)`) keeps the exact nanoTime timeline. While playing, `t = anchorSongMs + (nanoNow - anchorNanos)/1e6` and every frame the anchor is nudged toward `music.getPosition()*1000` (only when the reported position changed, and only while `music.isPlaying()`) with gain 0.1 and a hard resync if drift > 60 ms; **audio is never seeked during play**. Paused → time frozen. Resumed → the clock stays at the frozen time until the reported position moves (at most `MAX_START_LEAD_MS` = 400 ms), then takes that position; **on Android the song is first seeked to the frozen time** (`setReseekOnResume`, tests only): MediaPlayer's own clock runs on from a plain resume while the sound comes back later and some devices never win that back, so each pause left the music later than the chart (2026-10-15). Looping music (calibration) and a resume past the end of the file are not seeked.

**Offsets (binding, GAMEPLAY + SHELL agree; DESIGN §9.4/§9.5):**
* `judgeTime = clock.timeAtNanos(eventNanos) − audioOffsetMs`, where `audioOffsetMs` is the **active output's** offset from `device.json` (`profiles().device().audioOffsetMs()`, per output SPEAKER / WIRED / BT, clamped −300..300). Positive = the player hears audio late, so judge times shift later. Frame-based work (LOST sweep, holds, mines, autoplay) uses `clock.nowMs() − audioOffsetMs`.
* `visualTime = judgeTime + visualOffsetMs` (`device.json`, clamped −150..150). Notes, lines, lanes **and the hit-test geometry** (line y and lane spans used to resolve a touch) are evaluated at the visual time, i.e. where the player saw them. **A positive visual offset makes notes arrive earlier** (it compensates a display that shows frames late).
* `GameplayScreen` reads both values in `begin()` and again when the pause menu resumes (`GameEngine.setOffsets`), so a change applies on the next run or resume.
* Calibration APPLY stores `round(median(tap − beat))` (clamped −300..300) directly as the active output's audio offset, because calibration measures the raw clock with the same convention. The §9.5 visual test flashes at `nowMs − audioOffsetMs + visualOffsetMs`.

**Input timestamps.** `GameplayScreen` validates each event time against `clock.nanoTime()` (not `System.nanoTime()` directly): an event time ≤ 0, later than now or more than 1 s old falls back to now. A test that replaces the clock's time source with `setTimeSource(...)` must therefore also proxy `Gdx.input.getCurrentEventTime()` onto the same base, or every touch is judged at "now".

## 10. Gameplay contract (GAMEPLAY)

Per-lane cursor indices (no O(N) scans).

  * a **lift or key-up before `end − HOLD_RELEASE_GRACE_MS`** breaks the hold at once;

## 13. Lanes and note types — chart model v2 (owner change 2026-10-11, binding; overrides §8 lane rules and the 20-lane parts of §10)

### 13.1 Lanes
* A lane is identified by a **non-zero int id**, unlimited in both directions. Negative ids sit left of positive ids; lanes are laid out in ascending id order (…, −2, −1, 1, 2, …). Lane 0 is invalid (rejected at load, logged once) unless it is an inserted lane (below).
* Both judgement lines share **one** lane set (as today: sky lanes 10–19 always had the same x as 0–9). Each note says which line it belongs to.
* Each lane has two animated channels, evaluated with the existing `Events.calculateValue(list, beat, base)` (power-function easing `initial + (final − initial)·p^exponent`, times in beats):
  * `width` (base 240): a **relative weight**, ≥ 0 (negative values clamp to 0).
  * `opacity` (base 1.0, clamped 0..1): multiplies the lane's own visuals only (lane ticks, separators (the old guides; a separator takes the brighter of its two lanes), column glow, approach glow, key hint). It does **not** change note opacity; notes keep their own `DisappearEvents`.
* **Lane modes (owner 2026-10-13, chart key `laneCount`, `Chart.laneLimit()`) and camera frame (owner 2026-10-13 05:28).** There is no window any more: lanes show across the screen (reference `LaneLayout.VIEW_LEFT` 0 .. `VIEW_RIGHT` 1920, stretched with `Field.x`). The **camera frame** `c(t)` (`LineEvents.cameraFrame` / `cameraFrameEvents`, type `CameraFrame`, `JudgementLine.cameraFrameAt`; reference units, positive = right, always absolute beats) moves the central axis, the border between lanes −1 and +1, to `x = 960 + c·kx` (`LaneLayout.axis()`).
  * **Unlimited (default: no `laneCount`; v1 always)**: every lane keeps its width in reference units, times the global lane scale `g(t)` (`LineEvents.laneScale` / `laneScaleEvents`, `JudgementLine.laneScaleAt`); lanes 1, 2, … follow each other rightwards from the axis, −1, −2, … leftwards. The screen only clips: a lane that reaches onto the screen keeps its whole span, also past the edge (never squeezed); a lane wholly off screen has zero width (not drawn, not touchable). The loader adds default lanes (`Lane.implicit()`, not written back) for id gaps and to cover the screen at the smallest scale and the farthest camera frame, up to ±64. The stretch (`Field.kx`) scales the tiles about the axis. Scaling some lanes only (owner's "partial scaling") is their own `widthEvents`.
  * **Finite (`laneCount` N)**: the declared lanes divide the frame `axis ± 960·g·kx` (the whole screen at scale 1, camera 0; not clipped) **in proportion to their widths**: with `W = Σ wᵢ`, `s = (right − left) / W`, lane i spans `x = left + s·Σ_{j<i} wⱼ` to `+ s·wᵢ`. If `W ≤ 0`, every lane has zero width at `left`.
  * Default v2 chart: 8 lanes × 240 = 1920, scale 1, camera 0 → 240 ref units per lane, full screen width (same look as before).
  * A charter widens one lane → in a finite chart the others narrow to keep the field inside the frame; to grow the field instead, animate the scale. A lane animated from width 0 → 240 "slides in".
  * **Old window keys** (`leftBound/rightBound`, `leftEvents/rightEvents`, `Events.TYPE.LeftBound/RightBound`) are only read, never written. v1: the window becomes scale `(right − left) / 2400` and camera `(left + right) / 2 − 960`; window events in left/right pairs (same start, end, exponent) become one `LaneScale` and one `CameraFrame` event each, unpaired ones are dropped (logged). So −240..2160 is scale 1, camera 0, and the shipped 0..1920 squeeze is scale 0.8. A finite v2 chart with a window and no `laneScale` / `cameraFrame` keys converts the same way with span 1920; an unlimited v2 chart's window is ignored (logged).
* **Inserted lanes (owner 2026-10-15, chart key `insert` on a lane, CHART_FORMAT §3.6).** 「轨道插入事件……在两条轨道之间插入一个新轨道，并自动压缩已在屏幕内显示的轨道……初始大小（默认为0，但可以突然出现），最终大小（默认为插入这条轨道后所有在窗口内的轨道的大小），增长速度（默认为1）……"插入0号轨"」. `Lane.insert()` is an absolute `Width` event (start, end, initial 0, final = the mean base width of the nearest non-inserted lanes by id, a missing one counting 240, exponent 1); `Lane.widthAt` is 0 before it, follows it while it runs and is the normal width channel after it (base width = final). Missed groups go LOST together. Universal notes on the other line at the same time are a separate group (they need a tap in that line's zone). ## 17. Afterimage trails "拖拽残影" (owner request 2026-10-11, binding; looks in DESIGN §17)
The owner asked: every note can drag a string of copies of itself behind it while it falls, fainter and fainter; the copies are only a show (never hit); the charter sets how dense they are and how long they last; every note type has it; the tutorial teaches it. Reference: a Phigros screenshot where sideways-moving notes leave copies that "fall vertically".

* **Chart key** (v2 notes, every type: `tap`, `hold`, `mine`, `universal`; optional; absent = no trail):
  ```json
  "trail": { "length": 0.5, "density": 16, "alpha": 0.6, "fade": 1.0, "mode": "path", "from": 30, "to": 32 }
  ```
  * `length` (beats, ≥ 0): how far back in time the trail reaches. 0 = no trail.
  * `density` (copies per beat, > 0): copies are `1/density` beats apart. Copy count `n = min(MAX_TRAIL_COPIES = 32, floor(length·density + 1e-4))`; n = 0 → no trail.
  * `alpha` (0..1, default 0.6): opacity of the nearest copy relative to the note.
  * `fade` (default 1.0, clamped 0.05..20): copy k (k = 1 nearest … n farthest) has opacity `alpha · (1 − k/(n+1))^fade`, times the note's own opacity (`DisappearEvents`) at the copy's moment. Same power-curve idea as the chart events.
  * `mode`:
    * `"path"` (default): copy k is the note **exactly as it was** `k/density` beats ago: the lane x of that moment (LaneLayout and window evaluated at that beat), its distance from the line and the line's y at that beat, its angle, its size and (hold) its length. A note falling straight down leaves a straight column of copies behind it; a note in a lane that slides sideways leaves a slanted trail along its path; a rotating note leaves copies at its earlier angles.
    * `"level"`: copy k takes the note's **sideways position, lane width and angle** from `k/density` beats ago but keeps the note's **current** distance from the line, i.e. the copies fall straight down level with the note. That is the sideways smear of the owner's reference image (copies beside the note, not above it). A note that only falls straight down shows no level trail.
  * `from` / `to` (beats, optional): only copies whose moment lies in `[from, to]` are shown, so a charter can switch the trail on for part of the fall. `from > to` → swapped.
* **Visual only.** The engine never reads trails: copies are never judged, never touched, never counted, never block or consume input, never trigger FX or sounds. Mines' copies are not dangerous.
* **Lifetime of a copy** with moment `s = beat − k/density`:
  * drawn only when `s ≥ note.visibleFrom()` and `s ∈ [from, to]`, and the note's state at `s` is on screen (not `HIDDEN_POSITION`);
  * a note that was **hit** (any judgement but LOST) at beat `h`: `path` copies need `s < min(h, judgement)` — the trail drains into the line behind the vanished note; `level` copies disappear with the note;
  * a **missed** note (LOST, a mine that passed or was touched): copies keep following the note's miss slide and miss fade evaluated at `s`;
  * **hold**: copies sample head, body and tail at `s`, but never for `s ≥ judgement` (after that the head is pinned to the line and a copy would sit on the live hold);
  * TIDE (universal): the full-window bar is copied (window of that moment in `path`, current window offset sideways is meaningless so `level` uses the current window); the tide wash, the sync square and hit FX are never copied (**Replaced 2026-10-12:** "the tide sweep, sync outline/connectors", which no longer exist). As built: a TIDE drop's copy is the T4 look of its line (sky pearls, ground rolling wave, DESIGN §5.15, §17.1), mines' copies turn like their note, and a LANE MINE's copies are its head cap and column.
* **Model.** `elements/NoteTrail` (immutable value, pure Java): `length, density, alpha, fade, mode (PATH/LEVEL), from, to`, `copies()`, `spacingBeats()`, `alphaOf(int k)`, `NoteTrail.NONE`. `Note.trail()` never returns null. `ChartMapper` reads `trail` on v2 notes (key case-insensitive), sanitises (NaN/∞/negative length → 0, density ≤ 0 → NONE, alpha clamped 0..1, fade clamped, unknown mode → path, missing from/to → ±∞) and logs once per chart. v1 charts get no trails. Default-approach notes work the same (motion is a pure function of the beat).
* **Rendering** (gameplay owns it; `gameplay/TrailRenderer` or inside `NoteRenderer`):
  * copies of a line's notes draw **before (beneath) all live notes** of that line, farthest copy first, with the **same sprites** as the live note (NinePatch body, leading edge, rim; mine studs; tide diamonds), normal blend, no additive glow for copies;

## 18. Scoring v2 (owner's formula 2026-10-11, revised by the owner 2026-10-14, binding; overrides the score parts of §5, §13.2/§13.4 and DESIGN §11/§12 where they differ; looks in DESIGN §18)
* **Formula (2026-10-14).** With `t` = judged notes in the chart (`totalNotes`: taps, hold heads, every TIDE member; mines excluded), `r` = RESONANCE count, `e` = ECHO count, `m_r` = longest run of consecutive RESONANCE judgements (**resonance chain**), `r_p` = PERFECT count (RESONANCE with `|Δt| ≤ 1000/30 ms ≈ 33.33 ms`):
  ```
  score = 100,000,000 · (r + 0.55·e) / t + 10,000 · m_r / t + r_p
  ```
  The chain is a small bonus next to accuracy (at most 10,000), not a 10 % share of the score as in the 2026-10-11 formula `100,000,000 · (0.1 · m_r/t + 0.9 · (r + 0.55·e)/t) + r_p`. Exact integer form (no float drift, rounded down once): `base = floor((100,000,000 · (100·r + 55·e) + 1,000,000 · m_r) / (100·t))` in `long`, `score = base + r_p`. `t = 0` → 0. Maximum = `100,010,000 + t` (every note PERFECT). `base == 100,010,000` exactly when every note is RESONANCE. For the same play the new score is never lower than the old one, so best scores saved before 2026-10-14 need no conversion; replays overwrite them.
* **Two different streaks.**
  * **Combo** (shown in the HUD, used for FULL COMBO): consecutive RESONANCE **or** ECHO; reset by LOST, by a touched mine and by every LANE MINE contact. FULL COMBO = `maxCombo == x` and no mine touched (§13.2).
  * **Resonance chain** `m_r` (used in the score): consecutive RESONANCE only; reset by ECHO and LOST. A touched mine does **not** reset the chain, so touching a mine never changes the score (owner rule: "碰到不扣分但是断连击").
* **Constants** in `play.Judgement` (aliased by `Params`): `PERFECT_MS = 1000f/30f`, `WEIGHT_TIER2 = 0.55f` (ECHO), `MAX_SCORE = 100_000_000` (full accuracy term; the cap of grades, rating and EXP), `CHAIN_SCORE = 10_000` (full chain term), `MAX_BASE_SCORE = 100_010_000`, `static int baseScore(chain, resonance, echo, totalNotes)`, `static int chainScore(chain, totalNotes)` (the chain term alone, for the result breakdown), `static int maxScore(int totalNotes)` = `MAX_BASE_SCORE + totalNotes`, `static boolean isPerfect(float absDeltaMs)`. The three judgement grades stay RESONANCE / ECHO / LOST; PERFECT is a sub-count of RESONANCE, not a fourth grade (no new enum constant).
* **`ScoreKeeper`** (pure, allocation-free): `record(j, deltaMs)` also updates `perfect` (RESONANCE with `|Δt| ≤ PERFECT_MS`), `chain`/`maxChain`; `mineTouched()` resets combo only; `breakCombo()` resets both; `score()` = `baseScore() + perfectCount()`; `baseScore()`; `maxScore()`; `chain()`, `maxChain()`, `perfectCount()`; `earlyResonance()` / `lateResonance()` = RESONANCE hits that are not PERFECT with `Δt < 0` / `Δt > 0` (so PERFECT + early + late = r; `early()` / `late()` stay the ECHO-range hits beyond ±TIER1); `accuracy()` = (r + 0.55·e) / judged (ECHO weight 0.55 everywhere). The score is non-decreasing during a run.
* **`PlayResult`** gains `perfect`, `maxChain`, `baseScore`, `earlyResonance`, `lateResonance` (`Builder.resonanceEarlyLate`); `score` is clamped to `0 .. MAX_BASE_SCORE + totalNotes`, `baseScore` to `0 .. MAX_BASE_SCORE`. `RecordOutcome` unchanged in shape.
* **Grades** (DESIGN §18.3): `Rating.gradeOf(int score, boolean allResonance)`: PURE only when `allResonance`; otherwise by thresholds on `min(score, 99,999,999)`. `gradeOf(int score)` (records without the flag) treats `score ≥ 100,000,000` as PURE.
* **Rating, micro-goal, EXP** re-based on the 100 M scale (DESIGN §18.4–§18.5); all of them use `min(score, 100,000,000)` so the chain and PERFECT points above 100,000,000 never change rating, grade boundaries or EXP.
* **Stored records.** Profiles gain `scoreScale` (absent or 1 = old 10,000,000 scale). On load, a profile with `scoreScale < 2` has every `ChartRecord.bestScore` and `recent` entry multiplied by 10 (capped at 100,000,000), `bestGrade` recomputed with the new table (PURE kept as PURE), `bestRating` recomputed; then `scoreScale = 2` and the profile is saved (the `.bak` keeps the old file). `LegacyUserDataImporter` converts the old game's 10,000,000-scale scores the same way (×10). Unit tests cover both migrations and idempotence (loading twice never multiplies twice).
* **Display**: every score is shown with **9 digits** grouped (`099,812,345`; leading zeros dim) — HUD, result score decode, song card, list rows, browser rows, profile screen; scores above 100,000,000 show as `100,010,812`. Any code that assumed 8 digits or a 10,000,000 cap is updated (grep `10_000_000`, `99_999_999`, `MAX_SCORE`, `, 8, true`).
