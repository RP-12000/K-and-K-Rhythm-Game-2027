# K&K 谱面格式 v5 / v6（CHART_FORMAT）

**v6（2026-11-05 起，Kelvin「八轨改无轨，每个键横坐标也带移动数据」「把"轨道"这个概念去掉」）：没有轨道，每个键有自己的横坐标 `x` 和 `xEvents`，以屏幕中线为 0，见 §9。DRAG 和叠加层见 §10，悬浮键见 §11，定轨 / 无轨和判定区见 §12，自定义线条见 §13。** v5 及更早的谱面照样能读，读入时换成每个键的横坐标。下面 §0–§8 写的是 v5，v6 只有 §9 列出的不同。

v5 从 2026-10-27 起使用（Kelvin 04:12「把整个谱面文件全部重构」，04:40 选了「文件格式」）。和 v4 相比：

* **省掉默认值**：默认值一律不写，没写的键就是默认值。完全没有运动事件的音符用默认下落（判定前 2 拍，1080 → 0，匀速），不再每个音符写一遍。
* **一种写法**：键名全部小写开头、区分大小写，没有别名；事件列表都叫 `<通道>Events`，事件都写成 `{"beats": [开始拍, 结束拍], "values": [开始值, 结束值], "ease": 指数}`；残影、故障、扭曲都写成数组。
* **歌曲信息只写在 `song.json`**：歌名、曲师、画师、BPM、变速、offset 是整首歌的，只写一次；难度文件里只有这个难度自己的东西。
* 画面、判定和计分规则都和 v4 一样。规则的细节（缓动公式、无限轨 / 有限轨、插入删除轨道、TIDE STREAM、LANE MINE、残影、故障、漩涡、扭曲……）见 `CHART_FORMAT_v4.md`，本文只写 v5 的键。
* 旧格式（v1–v4）仍然能读：游戏和谱面编辑器读到旧文件时按 v4 的规则读取（代码在 `elements/LegacyChartFormat`），旧的 v1–v3 照样自动换算。写出一律是 v5（`elements/ChartFormatV5`）。
* 读取在 `elements/ChartMapper`，`song.json` 在 `elements/SongInfo`。代码和本文不一致时以代码为准，并请同时修正本文。

## 0. 文件

| 文件 | 内容 |
|---|---|
| `assets/Charts/<歌曲 id>/song.json` | 整首歌：`title`、`artist`、`illustrator`、`bpm`、`bpmList`、`offsetMs`，还有试听段、曲绘取景等（§1） |
| `assets/Charts/<歌曲 id>/Surface.json` 等 | 一个难度一个文件：`Surface.json`、`Shallow.json`、`Deep.json`、`Abyss.json`（屏幕上显示为 SHALLOW / MEDIUM / DEEP / ABYSS）。难度只看文件名 |
| `assets/Introduction/song.json`、`Surface.json` | 教程，写法一样 |

单位和 v4 一样：时间用拍（第 0 拍在音频的 `offsetMs` 毫秒处），位置用 1920 × 1200 的参考画面（x 从左往右，y 从下往上），下判定线默认 y = 120，上判定线默认 y = 1080。

## 1. `song.json`

```json
{
  "title": "Confusion",
  "artist": "Tectogen_海渊",
  "illustrator": "Large Language Model",
  "bpm": 197,
  "offsetMs": 596,
  "previewStartMs": 51154,
  "previewEndMs": 70647,
  "jacket16x9": { "x": 0, "y": 0, "w": 1, "h": 0.5625 }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `title` | 文件夹名 | 歌名 |
| `artist`、`illustrator` | `""` | 曲师、画师 |
| `bpm` | **必填** | 大于 0。有 `bpmList` 时写第一段的 BPM |
| `bpmList` | 不变速 | 变速：`[{"beat": 0, "bpm": 170}, {"beat": 64, "bpm": 85}]`，规则同 v4 §2.1 |
| `offsetMs` | 0 | 第 0 拍在音频里的毫秒数 |
| 其他键 | | `previewStartMs`、`previewEndMs`、`resultMusicStartMs`、`jacket16x9`、`jacketCircle`、`map` 同 v4 §12.2；谱面编辑器自己的键（例如 `previewStartBeat`）游戏不读 |

## 2. 难度文件的顶层

```json
{
  "format": 5,
  "charter": "Overwhelming Sensations",
  "constant": 14.9,
  "lines": { "upperEvents": [ { "beats": [231.5, 231.58], "values": [1080, 1110], "ease": 0.5 } ] },
  "notes": [
    { "type": "tap", "line": "upper", "lane": -2, "beat": 37 },
    { "type": "hold", "lane": -1, "beat": 9, "duration": 1, "height": 540 },
    { "type": "universal", "beat": 95.5 },
    { "type": "mine", "line": "upper", "lane": 2, "beat": 278.375,
      "positionEvents": [ { "beats": [278.125, 278.375], "values": [1300, 0] } ] }
  ],
  "editor": { "iterations": 84 }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `format` | **必填** | 写 `5`。没有这个键（或写的是旧的 `formatVersion`）就按旧格式读 |
| `charter` | `""` | 谱师 |
| `constant` | 没有定数 | 定数，数字（例如 `14.9`），也可以是文字 |
| `laneCount` | 无限轨 | 写了就是有限轨，同 v4 §3.2 |
| `lanes` | 8 条默认轨道 −4..−1、1..4 | 轨道（§3）。全是默认轨道时不写 |
| `lines` | 默认判定线 | 判定线、全局缩放、镜头平移（§4）。全是默认值时不写 |
| `veils` | 没有漩涡 | 漩涡（§6） |
| `fixedLanes` | 无轨 | 定轨 / 无轨分段（v6，§12） |
| `strokes` | 没有自定义线条 | 自定义线条：表演用、从不判定的直线或曲线（§13） |
| `notes` | 没有音符 | 音符（§5） |
| `editor` | | 谱面编辑器自己的数据（例如 `iterations` 迭代次数、`flowBpmList`、`fallBy`），游戏不读（§8） |
| `song` | | 只给离开歌曲文件夹单独存放的谱面（备份、测试）：写法同 `song.json` 的 `title` … `offsetMs`。同一文件夹有 `song.json` 时以 `song.json` 为准，歌曲文件夹里的谱面不写 |

其他键一律跳过。

## 3. 事件

```json
{ "beats": [35, 37], "values": [1080, 0], "ease": 0.5 }
```

| 键 | 默认 | 说明 |
|---|---|---|
| `beats` | **必填** | `[开始拍, 结束拍]`。两个一样就是瞬间跳到结束值 |
| `values` | **必填** | `[开始值, 结束值]` |
| `ease` | 1 | 缓动指数（v4 的 `exponent`）：1 匀速，大于 1 先慢后快，小于 1 先快后慢。`value = 开始值 + (结束值 − 开始值) · p^ease` |

* 一个通道在某一拍的值：最后一个已开始的事件还没结束就用它的值，**否则用基础值**（和 v4 一样，不是上一个事件的结束值）。要让值停住，就写一个开始值等于结束值的事件盖住那段时间。
* 事件按开始拍排序，同一通道里不要重叠。
* 谱面编辑器可以在事件里加自己的键（`rel`、`flow`、`link`、`grp`），游戏不读；`ChartUpgrade` 转换时原样带过去（§7、§9）。
* 叠加层（§10.2）的事件可以互相重叠，每层把自己的值加上去，不按这里「用最后一个事件」的规则。

## 4. 轨道 `lanes` 和判定线 `lines`

```json
"lanes": [
  { "id": -1, "width": 300, "widthEvents": [ { "beats": [16, 18], "values": [300, 240] } ] },
  { "id": 0, "insert": { "beats": [32, 34], "values": [0, 240] } },
  { "id": 3, "delete": { "beats": [60, 62], "values": [240, 0] } }
]
```

轨道键：`id`（必填）、`width`（默认 240）、`opacity`（默认 1）、`widthEvents`、`opacityEvents`、`insert`、`delete`。`insert` 和 `delete` 是一个事件（§3），意义同 v4 §3.6、§3.7。写了 `lanes` 就只有写出来的这些轨道（无限轨时中间缺的 id 和画面能露出的轨道照样自动补上）。

```json
"lines": { "upper": 1060, "lower": 120, "upperEvents": [], "lowerEvents": [], "scale": 0.8, "scaleEvents": [], "camera": 120, "cameraEvents": [] }
```

| 键 | 默认 | v4 里叫 |
|---|---|---|
| `upper`、`upperEvents` | 1080 | `upperJudgementLine`、`upperEvents` |
| `lower`、`lowerEvents` | 120 | `lowerJudgementLine`、`lowerEvents` |
| `scale`、`scaleEvents` | 1 | `laneScale`、`laneScaleEvents`（全局缩放） |
| `camera`、`cameraEvents` | 0 | `cameraFrame`、`cameraFrameEvents`（镜头平移） |
| `upperLayers`、`lowerLayers`、`cameraLayers` | 没有 | 同名，在 `LineEvents` 里（叠加层，§10.2） |

## 5. 音符 `notes`

| 键 | 默认 | 说明（v4 里叫） |
|---|---|---|
| `type` | **必填** | `tap` DROP 水滴、`hold` STREAM 水流、`mine` MINE 水雷、`universal` TIDE 浪花、`tideMine` TIDE MINE 浪花水雷（§5.1）、`drag` DRAG（§10.1） |
| `line` | `lower` | `lower` 地面线、`upper` 天空线 |
| `lane` | **轨道音符必填** | 轨道 id。`universal`、`tideMine` 不写 |
| `beat` | **必填** | 判定拍（`judgement`） |
| `duration` | 0 | 持续拍数。`hold` 必写；`universal` 写了是 TIDE STREAM，`mine` 写了是 LANE MINE，`tideMine` 写了是 TIDE STREAM MINE |
| `height` | 0 | 尾巴长度（hold、TIDE STREAM、LANE MINE） |
| `waveSpeed` | 0 | 只给 TIDE、TIDE STREAM（2026-10-28）：浪花每拍移动几个波，正数向右、负数向左，0 不动。地面线是波往旁边流，天上线是珍珠串往旁边移（一个波 = 两颗珍珠）。其他音符写了也忽略，不写回 |
| `fake` | 没写 | 假键（2026-11-02，Kelvin，给 `tap`、`hold`、`mine` 和 `universal` 浪花、潮汐（05:28 起），`tideMine` 写了忽略）：`true` 时只是装饰，画法和真的一样（移动、旋转、公转、横移、透明度、残影、故障、扭曲都照常），到判定拍（长条到结束拍）就不再画。不判定，不算音符数和水雷数，不计分、不算连击，没有打击效果和打击音，判定线上不发光提示，也不算多押（同一拍的真键不会因为它出多押提示）。假的浪花不和同一拍的浪花组成一组，每个都单独画（同一拍的真浪花样子一样时只画一个，位置、角度等不同时各画各的）。曲子结束的时间仍会等它画完 |
| `positionEvents` | 默认下落 | 离判定线的距离（`MovementEvents`）。不写就用默认下落；不在任何事件里的拍子音符在画面外 |
| `appear` | | 只给“没有接近”的音符：不写 `positionEvents`、`appear` 不早于 `beat` 时，音符不下落，判定时直接出现（v4 §9 的例外，`appearance`） |
| `rotationEvents` | 不转 | 角度（`RotationEvents`） |
| `opacityEvents` | 1 | 透明度（`DisappearEvents`） |
| `heightEvents` | 默认缩短 | 尾巴长度（`HeightEvents`），只给 hold、TIDE STREAM、LANE MINE |
| `xLayers`、`positionLayers`、`rotationLayers` | 没有 | 叠加层（2026-11-05，§10.2）：加在横坐标、离线距离、角度上 |
| `pivot` | `[0, 0]` | 自转中心 `[x, y]`，从音符自己的中心量起（v4 §6.1.1）。谱面编辑器里自转固定在键中心（长条是键头的中心，2026-10-29 20:55），不再填；游戏照旧读旧谱里写了的 `pivot` |
| `offsetX` | 0 | 只给轨道上的音符（2026-10-28）：画在轨道中心右边多少参考单位（负数往左；天地两条线都是屏幕向右，按 kx 拉伸）。先横移再按 `pivot` 旋转，`pivot` 从横移后的音符量起。只改画面，判定和打击效果仍在原轨道 |
| `offsetXEvents` | 用 `offsetX` | 横移随拍子变（2026-10-28，只给轨道上的音符，写法同 `positionEvents`）：事件里的值是那一拍的横移。有事件时，不在事件里的拍子横移是 0（回到轨道中心），常量 `offsetX` 只在没有事件时用（2026-10-29）。`pivot` 从横移后的音符量起 |
| `orbit` | 没有 | 公转中心（2026-10-29，只给轨道上的音符）：参考画面里的绝对坐标 `[x, y]`（1920 × 1200，y 从下往上，`[960, 600]` 是画面中心）。只写 `orbit` 时（2026-10-29 19:04 的写法），按音符自己的角度绕这一点转，不用 `pivot`；几个键写同一个点就整体转；角度 0、中心没动时，键就在没写 `orbit` 时的位置。再写了半径或公转角度（下面几行）就按半径和角度摆。在参考画面里算，再按场地拉伸（16:10 屏幕上形状不变，别的比例跟轨道一样横向拉伸）。只改画面 |
| `orbitXEvents`、`orbitYEvents` | 不动 | 公转中心随拍子移动（2026-10-29，写法同 `positionEvents`，值是绝对坐标），键跟着平移。和别的通道不同：事件结束后中心停在事件的终点，直到下一个事件；第一个事件之前在 `orbit`。没写 `orbit` 时忽略 |
| `orbitRadius`、`orbitRadiusEvents` | 没有 | 公转半径（2026-10-29 20:55，参考单位，事件写法同 `positionEvents`，像中心一样事件结束后停在终点；没写 `orbitRadius` 时第一个事件之前用它的起始值）。写了半径或公转角度，公转时段里键头的中心就在「公转中心 + 半径 × 公转角度的方向」，半径为负就伸到另一边；键自己的旋转只让它绕键头中心自转。公转时段从公转中心、半径、角度事件里最早的开始到最晚的结束（都没有事件就一直起作用），时段外键在自己的轨道上按「移动」落下。键什么时候显示仍看「移动」和透明度 |
| `orbitAngle`、`orbitAngleEvents` | 0 | 公转角度（2026-10-29 21:13，度，0° 朝右、逆时针为正，事件写法和停在终点同半径）。和键自己的「旋转」分开：公转角度在转、旋转不动，键就一直平行于判定线绕着转；两个写同样的转动就像辐条一样整体转 |
| `orbitConflict` | 没写 | 公转时段里「移动」给的键中心高度和公转不同（谱面编辑器的「物件坐标冲突」）时以谁为准：`"orbit"` 公转，`"move"` 高度用「移动」、横坐标仍用公转。没写时游戏按公转画，谱面编辑器提醒去选 |
| `orbitRigid` | 没写 | 刚性公转（2026-11-02，Kelvin，只对写了 `orbitRadius` 或 `orbitAngle` 的公转）：`true` 时半径横竖按同一个比例缩放，不是 16 : 10 的屏幕上公转出来的形状不会被压扁，每条「臂」的方向和键自己的旋转对得上。缩放比例取场地的竖向比例 `ky`（2026-11-04 起；以前取横向、纵向里小的那个 `min(kx, ky)`）：16 : 10 及更宽的屏幕上和以前完全一样，只有比 16 : 10 更窄的屏幕（4 : 3 平板）不再按横向缩小。公转中心照旧按位置拉伸，键本身的大小和旋转不变。没写时和以前一样（横按 kx、竖按 ky） |
| `trails` | 没有 | 残影，数组：`{"length", "density", "alpha", "fade", "mode", "from", "to"}`（v4 §6.8 的 `trail`） |
| `glitches` | 没有 | 故障，数组：`{"from", "to", "intensity", "intensityEnd", "ease", "rate", "split", "slice", "flicker"}`（v4 §6.9 的 `glitch`；`exponent` 改叫 `ease`） |
| `distortions` | 没有 | 扭曲，数组：`{"from", "to", "intensity", "intensityEnd", "ease"}`（v4 §6.11 的 `distortion`） |

残影、故障、扭曲里各个键的默认值和取值范围同 v4。`from` / `to` 不写就是不限。

同一条线、同一轨道、同一拍可以放几个 `tap` / `hold`（2026-11-02 起，Kelvin），读取时都保留，每个都是单独的音符：一次按下只判一个，叠了几个就要几根手指。以前读取时只留一个。

### 5.1 浪花水雷 `tideMine`（2026-10-31）

浪花和潮汐的水雷版本：画成那条线的浪花（地面是波浪、天上是珍珠串，带 `duration` 时后面跟潮汐的长条），颜色是水雷红。键同 `universal`（没有轨道、横移、公转）。不算进音符总数，算进水雷数；碰到时断连击，分数加 10,000（2026-11-01 起，见 CHART_FORMAT_v4 §6.4），自动播放从不碰。

* **浪花水雷**（不写 `duration`）：判定区里任何位置按下就算碰到，±133.33 ms，只算按下的那一下。同一条线上它的判定窗和别的音符（所有轨道的 DROP、STREAM 头，还有浪花）重叠时，按普通水雷的规则互扣（v4 §6.4）：水雷让出那个音符的共鸣窗，那个音符的回响窗扣掉水雷窗。
* **潮汐水雷**（写了 `duration`）：像轨道水雷，只是封住整条线的判定区：到线后到结束 `[T, end)`，手指在判定区里（按下、停着、滑进来）或按着这条线的键，每碰一次断一次连击，离开后才会再算。同一条线上共鸣窗碰到它的音符先判，那个音符没有回响；打出共鸣后这条线的潮汐水雷睡 150 ms（v4 §6.4.1 的让位和保护，只是按整条线算）。

## 6. 漩涡 `veils`

```json
"veils": [
  { "shape": "circle", "radius": 210, "x": 1480, "y": 322, "from": 112, "to": 130,
    "opacityEvents": [ { "beats": [112, 113], "values": [0, 1] } ] }
]
```

键：`shape`（`circle` / `polygon`）、`radius` 或 `points`（`[[x, y], …]`）、`x`（默认 960）、`y`（默认 600）、`rotation`（0）、`opacity`（1）、`from` / `to`（显示的拍数范围，v4 的 `startTime` / `endTime`，不写就是不限）、`xEvents`、`yEvents`、`rotationEvents`、`opacityEvents`、`glitches`、`distortions`。规则同 v4 §6.10。

### 6.1 水帘 `curtains`

```json
"curtains": [
  { "shape": "polygon", "points": [[-300, -560], [300, -560], [300, 560], [-300, 560]], "x": 1260,
    "from": 64, "to": 96, "blur": 24, "blurEvents": [ { "beats": [64, 66], "values": [0, 24] } ] }
]
```

纯演出：把盖住的画面整个模糊（轨道、音符、漩涡、判定线、打击特效、连击数、判定字、四角的分数和暂停键都一样），只有暂停菜单不受影响；从不判定，点在上面照常判定。键同 `veils`（`distortions` 让边缘摆动，`glitches` 不画），另加 `blur`（模糊半径，参考坐标单位，默认 16，0–64，超出范围读入时修正）和 `blurEvents`（按拍变化，同其他事件）。边缘柔和，里面有细细的水痕往下流，颜色偏冷一点；中心和形状都跟漩涡一样随屏幕比例拉伸（横向乘 屏幕宽 / 1920、纵向乘 屏幕高 / 1200）。

## 7. 从旧格式转换

* 游戏和谱面编辑器都能读旧文件；写出时一律写 v5。
* 一次性转换工具：`ChartUpgrade`（把一个文件夹里所有旧谱面转成 v5，同时把歌曲信息写进 `song.json`，保留 `song.json` 原有的键）。转换前后逐个音符比对，一致才写入。
* 旧文件里谱面编辑器的键（`iterations`、`flowBpmList`、`fallBy`）放进 `editor`，事件上的 `rel`、`flow`、`link`、`grp` 原样保留（音符、叠加层和判定线的事件都是）。

## 8. 谱面编辑器写出的内容

* 歌曲文件夹里的谱面文件只写本难度的东西（§2），不写 `song`；歌名、曲师、画师、BPM、变速、offset 写进 `song.json`，保留 `song.json` 原有的键（`SongInfo.mergeInto`）。
* 编辑器自己的数据放在顶层 `editor` 里（`iterations`、`flowBpmList`、`fallBy` 等），事件上的编辑器键（`rel`、`flow`、`link`、`grp`）直接写在那个事件里。游戏都不读。
* 不写 `positionEvents` 的音符是默认下落，编辑器按“跟着判定拍走”（`rel` 为 true）处理。改成绝对拍数的默认下落要照常写出 `positionEvents`，并在事件里写 `"rel": false`。
* 默认值不写；写了默认值也能读，只是文件大一些。

## 10. DRAG 和叠加层（2026-11-05）

### 10.1 `drag`：DRAG

Kelvin 2026-11-05：「加 Drag，手指在对应判定线就判」「手指提前放着或者滑过去都算，到点时手指在那儿就是共鸣，不在就是迷失，没有回响」。

```json
{ "type": "drag", "line": "upper", "x": -240, "beat": 48 }
```

* 键同 `tap`：v6 写 `x` / `xEvents`，v5 写 `lane`（横移照旧）；移动、旋转、公转、透明度、残影、故障、扭曲、`fake` 都照常。`duration`、`height` 写了也忽略。v4 工作文本里一样写 `"type": "drag"`。
* 不用按，只看手指在不在：从判定拍前 133.33 ms 到判定窗结束（判定拍后 133.33 ms），任何一根按着的手指（在漩涡里按下的不算）在这条线的判定区里、离键中心不超过 0.8 个键宽（键宽的一半再加两边各 30%，和点键时够得着旁边的键一样远），就接住这个 DRAG。每个触摸事件和每一帧都看，手指提前停在那里、滑过去、按下去都算。
  * 判定拍之前接住：到判定拍时判共鸣。
  * 判定拍或之后接住：马上判共鸣。
  * 一直没接住：判定窗结束时迷失。没有回响。
* 按着长条的手指、正在点别的键的手指也能接住；接住不占用手指，也不挡别的键。
* 计分：算一个音符（音符数、连击、共鸣链都算）；Δt 记 0，算一个 PERFECT（±33 ms 以内），不进早晚统计。
* 和水雷：长水雷在它的位置时，像让 DROP 一样让它（它的判定窗只到判定拍后 66.67 ms；打出共鸣后那个位置的长水雷睡 150 ms，CHART_FORMAT_v4 §6.4.1）。普通水雷要按下才算，DRAG 不用按，所以两者互不影响。
* 自动播放：在判定拍判共鸣。打击音和打中效果同 DROP 的共鸣；提前接住时，打击音按判定拍排好，到点才响。

### 10.2 叠加层

Kelvin 2026-11-05，和谱面编辑器商定：同一个通道可以有好几层互相重叠的事件，每层在自己的拍子里把值加到原来的值上。

```json
"xLayers": [
  { "beats": [16, 18], "values": [0, 120] },
  { "beats": [17, 19], "values": [0, -60], "ease": 2 }
]
```

| 写在哪里 | 键 | 加在 |
|---|---|---|
| 音符 | `xLayers` | 横坐标（`tap`、`hold`、`mine`、`drag`；浪花类写了忽略）。也改判定的位置 |
| 音符 | `positionLayers` | 离判定线的距离。只在音符自己的「移动」让它显示时加（不在任何移动事件里、在画面外的拍子不加）；长水雷到线后固定在线上，不加 |
| 音符 | `rotationLayers` | 角度（度）。长水雷到线后固定的角度也算上判定拍那一刻的叠加层 |
| `lines` | `upperLayers`、`lowerLayers` | 天线、地线的高度。判定区跟着线走 |
| `lines` | `cameraLayers` | 镜头平移 |

* 每层是一个事件（§3 的写法；v4 工作文本用 v4 写法 `startTime` / `endTime` / `initialVal` / `finalVal` / `exponent`）。从开始拍到结束拍，把缓动后的值加上去；不在任何一层里的拍子加 0。
* 层可以互相重叠，重叠的拍子都加上。
* 结束拍算上，除非同一个列表里有另一层正好从这一拍开始（接力：交接的那一拍只加下一层，不会加两次）。开始拍和结束拍一样的层只在那一拍加。
* 原来的值照旧按 §3 算（事件外用基础值），叠加层只加偏移。所以 v6 的 `xLayers` 也是偏移，不按中线换算。
* 没有透明度的叠加层。v1 谱面不读叠加层。
* 写在 v5、v6 的音符和 `lines` 里；v4 工作文本里音符的键同名，判定线的写在 `LineEvents`（或 `judgementLine`）里，键也同名。
* 谱面编辑器写在叠加层事件上的键（`rel`、`flow`、`link`、`grp`）游戏不读，转换时原样带过去。

### 11.1 键

| 键 | 默认 | 说明 |
|---|---|---|
| `float` | | `true` 是悬浮键。`tap`、`hold`、`drag`、`mine`（写了 `duration` 的是长水雷，7.186 起）能悬浮；`universal`、`tideMine` 写了照旧在线上（读谱报告会说） |

| `y` | 600 | 中心的纵坐标，0–1200，从下往上量（600 是屏幕正中） |
| `size` | 水滴、水流 250，DRAG 190，水雷 190，长水雷 220（7.188 起；之前 160、120、120、140） | 直径。不是正数时用默认；画和判都限制在 2–2400 |

| `glitches`、`distortions` | | 故障、扭曲（7.187），写法和线上的键一样（CHART_FORMAT_v4 §6.9、§6.11）：整个悬浮键（空泡泡、玻璃球、外圈）一起撕成横条、红蓝色散、闪，或者像水一样晃 |

* 悬浮键不在线上：`line`、`lane`、`positionEvents`、`rotationEvents`、`pivot`、`orbit`、残影、叠加层写了都不管。
* **屏幕**：中心的横坐标像键的 `x` 一样跟着全局缩放、镜头和场地横向拉伸，纵坐标跟着场地纵向拉伸；永远是正圆，直径乘全局缩放和场地的纵向比例 `ky`。
* 悬浮键不看 `fixedLanes`（§12）。

### 11.2 填充 `fillEvents`

填充是「颜色离泡泡的边还有多远」，用直径量：

* `0` 是正好填满，该点的时候；等于直径是空的；比 0 小是溢出到边外；比直径大是越过了中心、从另一边出来。
* 画出来的颜色是一个直径为 |直径 − 填充| 的圆，圆心就是泡泡中心。
* **不写 `fillEvents`**：从出现时的空匀速填到判定拍正好满，之后接着往外溢（晚了的手指看得到）。填充跟着当时的直径算。`appear` 等于 `beat` 时一出现就是满的。
* **写了 `fillEvents`**：第一个事件之前是它的开始值；两个事件之间停在前一个的结束值；最后一个事件以后按它结束时的速度接着变（像过了线的键）。

### 11.3 判定

* **只认圈里**：按下时，手指要在这个键此刻画出来的圆里（1 个半径以内）才算；在不在判定区都一样。
* **一下只判一个键**：按下时，线上能判的键和圈里、判定窗里的悬浮水滴、水流头一起比，判最早的那个；一样早时线上的键先，再是中心离手指最近的（按各自的半径算）。
* **不跟别的键一起判**：没有浪花组、不连带另一条线。同一时刻的两个悬浮键要两根手指。
* 判定窗和线上的键一样：±66.67 ms 共鸣，±133.33 ms 回响，过了 +133.33 ms 还没判就是迷失。
* **悬浮水流**：打中头的手指按住；手指可以离开中心 1.3 个半径（键移动时跟着走），离开超过 0.1 秒就断（迷失）；放开和线上的长条一样（结束前的宽限以内放开算完成）。暂停时抬起的，恢复后 0.1 秒内在 1.3 个半径以内按下就接上。
* **悬浮 DRAG**：判定窗里，任何一根手指（在漩涡里按下的不算）在圈里就接住，判定拍判共鸣；判定拍以后才接住的马上判共鸣；没人接就是迷失。
* **悬浮水雷**（7.186）：只有按下才算，判定拍 ±133.33 ms 以内按在圈里就踩中。**悬浮长水雷**：从判定拍到结束，有手指在圈里（按下的、滑进来的、一直按着的）就踩中。踩中和线上的水雷一样：断连击、分数加 10,000，每个最多一次。
* **和键重叠**（照 2026-10-31 线上水雷和同轨键的规矩，只是看手指在哪）：水雷和键只要有一个是悬浮的，就不看轨道、只看时间配对；按下（或手指）的地方同时在两个圈里时，在键的共鸣窗（±66.67 ms）以内判键、水雷不算，在回响窗里不判键、水雷算（长水雷底下一直不判回响）；打出共鸣的手指底下的长水雷睡 150 ms。按在键上、不在水雷上的地方，回响照旧，所以键的判定窗不变短。DRAG 过了判定拍 66.67 ms 以后，在和它配对的水雷上的手指接不住它。
* 自动播放：判定拍判共鸣，从不碰水雷。

## 12. 定轨 / 无轨 `fixedLanes` 和判定区（2026-11-06）

Kelvin 2026-11-06 14:45「判定线和这个都不用垂判了」；14:55 分定轨、无轨两种，定轨留竖的分隔线、所有键都能用、可以写小数轨道，默认 6K；15:38「判定线上的按键默认大小设置为原来8K的大小」。22:23「改回半垂判」：7.189 起判定区又是上下各 480。

* **判定区**：每条判定线上下各 **480**（半垂判：两条线在默认位置时一条管上半屏、一条管下半屏；7.184–7.188 是上下各 160，只认落点附近）。判定区跟着线移动，16 : 10 以外的屏幕跟着拉伸（16 : 9 上是 432）。浪花停在离线远的地方、到判定拍才跳到线上时，它停的地方上下各 480 也算这条线的判定区（Kelvin 2026-10-16「有时候tide也能充当判定线」）。
* **顶层 `fixedLanes`**：按拍子分段写轨道数。

  ```json
  "fixedLanes": [{ "beat": 0, "count": 6 }, { "beat": 64, "count": 0 }, { "beat": 96, "count": 4 }]
  ```

  * `count`：从这一拍起，两条判定线之间平分成几条轨道，画竖的分隔线（定轨）；`0` = 无轨，不画分隔线。整数 0–32。
  * 第一段从 0 拍或更早开始时，它之前也按它算；从后面开始时，它之前是无轨。没写 `fixedLanes` = 整张谱都是无轨。谱面编辑器新建的谱默认写 `[{ "beat": 0, "count": 6 }]`（6K）。
  * 同一拍写了两段，后写的算。拍子不是数、`count` 不是 0–32 的整数的段，读取时丢掉（加载报告里有记录）。
  * 换段时，分隔线在换段前后各 1/4 拍里淡入淡出。
* **轨道只是参考线和判定宽度**：键照旧写自己的 `x`。k 条轨道的第 j 条（从 1 数，可以是小数）中心在 `x = −960 + (j − 0.5) × 1920 / k`。6K 是 −800、−480、−160、160、480、800；第 2.5 条在第 2、3 条的分界线上（−320）。
* **键的大小和判定宽度**：键都画 240 宽（原来 8K 一条轨道的宽度）。定轨里判定线上的键至少按一条轨道宽判：6K 是 320，4K 是 480，8K 和更多轨道就是键宽 240；无轨里按键宽 240。用判定宽度量：手指在判定宽度以内算这个键，附近没有这样的键时两边各多 30% 也算；按住长条时离键中心不超过 1.5 个判定宽度；DRAG 0.8 个；水雷看中间 70%，长水雷中间 80%。都按键的判定拍所在那一段的轨道数算。
* 浪花、潮汐、浪花水雷、潮汐水雷不变：整条线都算。悬浮键不看 `fixedLanes`。
* 读旧格式（v5 及更早、谱面编辑器的 v4 工作文本）也认 `fixedLanes`，写法一样。

## 13. 自定义线条 `strokes`（2026-11-06）

Kelvin 2026-11-06 18:44「然后加那种自定义线条，可以自己画在上面，曲线直线都可以。……这种自定义线条是表演用的，也可glitch，透明，distort，并且要和drag的那种线条做区分」；样子照效果图 v4（19:03「其他的都行」）。只是画面：从不判定，不挡手指，不算键数。

```json
"strokes": [
  { "points": [[-900, 1000], [-470, 880], [-120, 980], [240, 860], [620, 960]], "curve": true,
    "from": 13, "to": 21, "drawIn": 1.5, "drawOut": 1 },
  { "points": [[-880, 620], [880, 620]], "from": 14, "to": 21, "color": "#9FE8FF",
    "glitches": [{ "from": 15, "to": 21 }] },
  { "points": [[0, 340], [247, 520], [247, 680], [0, 860], [-247, 680], [-247, 520]], "curve": true,
    "closed": true, "front": true, "width": 3, "opacity": 0.35,
    "opacityEvents": [{ "beats": [16, 17], "values": [0.35, 1] }], "distortions": [{ "from": 16, "intensity": 2 }] }
]
```

| 键 | 默认 | 说明 |
|---|---|---|
| `points` | **必填** | 点，每个写 `[x, y]`（也可以写 `{"x": …, "y": …}`），和悬浮键的中心一样量：x 从屏幕中线量、负的在左，y 0–1200 从下往上。至少 2 个，最多 256 个（多的不要）。不是两个数、或者离得比 20000 还远的点丢掉；剩下不到 2 个点的整条丢掉 |
| `curve` | `false` | `true`：一条穿过每个点的平滑曲线；否则是点和点之间的直线 |
| `closed` | `false` | `true`：最后一个点再连回第一个点（至少 3 个点，不够就不连） |
| `front` | `false` | `true`：画在所有键上面；否则画在键下面（浪花、潮汐也在它上面） |
| `from`、`to` | 一直显示 | 从哪一拍到哪一拍显示（两头都算）。写反了对调 |
| `drawIn` | 0 | 从 `from` 起用几拍从第一个点一路画到最后一个点（两头慢、中间快），画的时候笔尖亮一点；0 是一下子出现 |
| `drawOut` | 0 | 在 `to` 之前几拍开始从第一个点收回，到 `to` 收完；没写 `to` 时不收 |
| `width` | 4 | 线宽，最大 200 |
| `color` | `"#EAF2FF"`（和双押线一样的墨白） | `"#RRGGBB"`，或者带透明度的 `"#RRGGBBAA"`（`#` 可以不写） |
| `opacity` | 1 | 透明度 0–1 |
| `opacityEvents` | | 透明度事件，和键的一样：事件里用事件的值，事件外用 `opacity`；超过 1 会闪 |
| `glitches`、`distortions` | | 故障、扭曲，写法和键的一样（CHART_FORMAT_v4 §6.9、§6.11）。故障：线断成一段一段横跳、少几段、带红蓝色散，或者暗下去闪；扭曲：每个点像水一样晃，强度和键一样 |

* **和 DRAG 的线分开**：DRAG 的线是紫色、半透明、两个 DRAG 之间的直线，跟着判定走；自定义线条默认是细的墨白线，外面一圈柔光，圆头，想画什么形状都行，不连键。
* **放在哪里**：点和悬浮键的中心一样，横坐标跟着全局缩放、镜头和场地横向拉伸，纵坐标跟着场地纵向拉伸；线宽乘全局缩放和场地的纵向比例。不跟判定线动，不看 `fixedLanes`。
* **画的顺序**：`front` 不是 `true` 的先画（在浪花、潮汐和所有键下面），然后画键，最后画 `front` 的（在悬浮键上面）；同一层按文件里的顺序。
* **读谱报告**：丢掉的条数（`N custom line(s) dropped`）、改过值的条数（`N custom line(s) fixed`：丢了点、`from` / `to` 对调、线宽或透明度超出范围、颜色看不懂、点太少不能闭合）。写成 `null` 的值按默认，不算改过。
* **其他格式**：v5 也认 `strokes`，写法一样。谱面编辑器的 v4 工作文本也一样，只是事件用 v4 写法，故障、扭曲也可以写成 `glitch`、`distortion`；事件上的 `rel` / `flow` / `link` / `grp` 由 `ChartUpgrade` 照样带进 v6（按线条在文件里的顺序对上）。
* 写谱面时，默认值都不写；`strokes` 写在 `notes` 前面，没有线条就不写这个键。
