# K&K 谱面格式 v5（CHART_FORMAT）

v5 从 2026-10-27 起使用（Kelvin 04:12「把整个谱面文件全部重构」，04:40 选了「文件格式」）。和 v4 相比：

* **省掉默认值**：默认值一律不写，没写的键就是默认值。完全没有运动事件的音符用默认下落（判定前 2 拍，1080 → 0，匀速），不再每个音符写一遍。
* **一种写法**：键名全部小写开头、区分大小写，没有别名；事件列表都叫 `<通道>Events`，事件都写成 `{"beats": [开始拍, 结束拍], "values": [开始值, 结束值], "ease": 指数}`；残影、故障、扭曲都写成数组。
* **歌曲信息只写在 `song.json`**：歌名、曲师、画师、BPM、变速、offset 是整首歌的，只写一次；难度文件里只有这个难度自己的东西。
* 画面、判定和计分规则都和 v4 一样。规则的细节（缓动公式、无限轨 / 有限轨、插入删除轨道、TIDE STREAM、LANE MINE、残影、故障、漩涡、扭曲……）见 `CHART_FORMAT_v4.md`，本文只写 v5 的键。
* 旧格式（v1–v4）仍然能读：游戏和谱面编辑器读到旧文件时按 v4 的规则读取（代码在 `elements/LegacyChartFormat`），旧的 v1–v3 照样自动换算。写出一律是 v5（`elements/ChartFormatV5`）。
* 读取在 `elements/ChartMapper`，`song.json` 在 `elements/SongInfo`。代码和本文不一致时以代码为准，并请同时修正本文。
* **谱面版本 2.0（v7，2026-11-09 起）**：Kelvin 把谱面重新定义成「简单函数」，见 §9。Kelvin 2026-11-10 定了这一版叫谱面版本 2.0，以后格式每改一次加 0.1（2.1、2.2…）；文件里还是写 `"format": 7`，代码里还叫 v7。游戏读到 v5 和更旧的文件时先换成 v7 再播放。

## 0. 文件

| 文件 | 内容 |
|---|---|
| `assets/Charts/<歌曲 id>/song.json` | 整首歌：`title`、`artist`、`illustrator`、`bpm`、`bpmList`、`offsetMs`，还有试听段、曲绘取景等（§1） |
| `assets/Charts/<歌曲 id>/Shallow.json` 等 | 一个难度一个文件：`Shallow.json`、`Medium.json`、`Deep.json`、`Abyss.json`，和屏幕上显示的 SHALLOW / MEDIUM / DEEP / ABYSS 一致（2026-11-10 起）。旧命名 `Surface.json`、`Shallow.json`、`Deep.json`、`Abyss.json` 照样认：文件夹里有 `Surface.json` 就按旧命名读（那时 `Shallow.json` 是 MEDIUM）。难度只看文件名 |
| `assets/Introduction/song.json`、`Shallow.json`（旧命名 `Surface.json`） | 教程，写法一样 |

单位和 v4 一样：时间用拍（第 0 拍在音频的 `offsetMs` 毫秒处），位置用 1920 × 1200 的参考画面（x 从左往右，y 从下往上），下判定线默认 y = 120，上判定线默认 y = 1080。

## 1. `song.json`

```json
{
  "title": "Confusion",
  "artist": "Tectogen_海渊",
  "illustrator": "Large Language Model",
  "bpm": 197,
  "offsetMs": 596,
  "previewStartMs": 51154,
  "previewEndMs": 70647,
  "jacket16x9": { "x": 0, "y": 0, "w": 1, "h": 0.5625 }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `title` | 文件夹名 | 歌名 |
| `artist`、`illustrator` | `""` | 曲师、画师 |
| `bpm` | **必填** | 大于 0。有 `bpmList` 时写第一段的 BPM |
| `bpmList` | 不变速 | 变速：`[{"beat": 0, "bpm": 170}, {"beat": 64, "bpm": 85}]`，规则同 v4 §2.1 |
| `offsetMs` | 0 | 第 0 拍在音频里的毫秒数 |
| 其他键 | | `previewStartMs`、`previewEndMs`、`resultMusicStartMs`、`jacket16x9`、`jacketCircle`、`map` 同 v4 §12.2；谱面编辑器自己的键（例如 `previewStartBeat`）游戏不读 |

## 2. 难度文件的顶层

```json
{
  "format": 5,
  "charter": "Overwhelming Sensations",
  "constant": 14.9,
  "lines": { "upperEvents": [ { "beats": [231.5, 231.58], "values": [1080, 1110], "ease": 0.5 } ] },
  "notes": [
    { "type": "tap", "line": "upper", "lane": -2, "beat": 37 },
    { "type": "hold", "lane": -1, "beat": 9, "duration": 1, "height": 540 },
    { "type": "universal", "beat": 95.5 },
    { "type": "mine", "line": "upper", "lane": 2, "beat": 278.375,
      "positionEvents": [ { "beats": [278.125, 278.375], "values": [1300, 0] } ] }
  ],
  "editor": { "iterations": 84 }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `format` | **必填** | 写 `5`。没有这个键（或写的是旧的 `formatVersion`）就按旧格式读 |
| `charter` | `""` | 谱师 |
| `constant` | 没有定数 | 定数，数字（例如 `14.9`），也可以是文字 |
| `laneCount` | 无限轨 | 写了就是有限轨，同 v4 §3.2 |
| `laneWidth` | 不写：按以前的样子算（§4） | 默认轨道的宽度（参考坐标，缩放 1 时）。每条轨道用自己的宽度，加减轨道不挤别的（§4，7.213；7.214 起所有有限轨的谱都这样）。新建的谱写 320；存盘总是写出 |
| `lanes` | 8 条默认轨道 −4..−1、1..4 | 轨道（§4）。全是默认轨道时不写。谱面编辑器新建的谱写 6 条（`laneCount: 6`，−3..−1、1..3，2026-11-07） |
| `laneless` | 没有无轨时间 | 无轨时间：`[{"from": 32, "to": 48}]`，这段时间不画轨道（§5.3，2026-11-07） |
| `fullScreen` | 没有全屏判定 | 全屏判定的段落：`[{"from": 32, "to": 48}]`，这段时间按屏幕哪里都算（§5.5，2026-11-07） |
| `view` | 默认视角 | 3D 视角：偏航、俯仰、视场角、距离四个通道的事件（§5.6，2026-11-07） |
| `seas` | 没有海面 | 海面：深蓝色的面，键和浪花可以落在上面，只是画面（§5.7，2026-11-07） |
| `lines` | 默认判定线 | 判定线、全局缩放、镜头平移（§4）。全是默认值时不写 |
| `veils` | 没有漩涡 | 漩涡（§6） |
| `notes` | 没有音符 | 音符（§5） |
| `editor` | | 谱面编辑器自己的数据（例如 `iterations` 迭代次数、`flowBpmList`、`fallBy`），游戏不读（§8） |
| `song` | | 只给离开歌曲文件夹单独存放的谱面（备份、测试）：写法同 `song.json` 的 `title` … `offsetMs`。同一文件夹有 `song.json` 时以 `song.json` 为准，歌曲文件夹里的谱面不写 |

其他键一律跳过。

## 3. 事件

```json
{ "beats": [35, 37], "values": [1080, 0], "ease": 0.5 }
```

| 键 | 默认 | 说明 |
|---|---|---|
| `beats` | **必填** | `[开始拍, 结束拍]`。两个一样就是瞬间跳到结束值 |
| `values` | **必填** | `[开始值, 结束值]` |
| `ease` | 1 | 缓动指数（v4 的 `exponent`）：1 匀速，大于 1 先慢后快，小于 1 先快后慢。`value = 开始值 + (结束值 − 开始值) · p^ease` |
| `curve` | 没有 | 自定义缓动曲线（2026-11-07，7.207）：写了就不看 `ease`（存盘时也不写 `ease`）。见下面 |

* 一个通道在某一拍的值：最后一个已开始的事件还没结束就用它的值，**否则用基础值**（和 v4 一样，不是上一个事件的结束值）。要让值停住，就写一个开始值等于结束值的事件盖住那段时间。
* 事件按开始拍排序，同一通道里不要重叠。
* 谱面编辑器可以在事件里加自己的键（例如 `rel`、`flow`），游戏不读。
* **自定义曲线 `curve`**（Kelvin 2026-11-07 19:48：「然后把那些曲线做好-->这样子能自定义捏合曲线」）：一串数 `[0, 0, c1x, c1y, c2x, c2y, x1, y1, …, 1, 1]`，共 6n + 2 个（n ≥ 1 段三次贝塞尔）：每段是起点、两个控制点、终点，下一段从上一段的终点接着走。x 是事件里经过的时间比例（0 = 开始拍，1 = 结束拍），往后不减；y 是进度（0 = 开始值，1 = 结束值），可以超过 0..1（冲过头再回来）。`value = 开始值 + (结束值 − 开始值) · y(p)`。所有通道的事件都能写（音符、判定线、轨道、视角、海面），故障和扭曲的强度渐变也能写（§5，7.208）；旧格式的事件（谱面编辑器的工作文本）也认同名的键。
  * 读的时候整理一下：第一个点当作 (0, 0)、最后一个当作 (1, 1)；中间端点的 x 不小于前一个、不大于 1；控制点的 x 夹到它那一段的两端之间，这样每段的 x 都是往前走的，一个时间只对应一个值。个数不是 6n + 2、有不是数字的值，就当没写 `curve`（照 `ease` 算）。
  * 曲线模板是谱面编辑器自己的东西，谱面文件里只写曲线本身。

```json
{ "beats": [8, 12], "values": [1080, 980], "curve": [0, 0, 0.3, 1.5, 0.7, 1.2, 1, 1] }
```

## 4. 轨道 `lanes` 和判定线 `lines`

```json
"lanes": [
  { "id": -1, "width": 300, "widthEvents": [ { "beats": [16, 18], "values": [300, 240] } ] },
  { "id": 0, "insert": { "beats": [32, 34], "values": [0, 240] } },
  { "id": 3, "delete": { "beats": [60, 62], "values": [240, 0] } }
]
```

轨道键：`id`（必填）、`width`（默认 240）、`opacity`（默认 1）、`widthEvents`、`opacityEvents`、`insert`、`delete`。键（DROP、STREAM、DRAG）就是柱子底面那么大（Kelvin 2026-11-09 14:25：「轨道上的键就直接一致为柱子底面大小」；7.200–7.217 是轨道宽 × 240 / `laneWidth`）：写了 `laneCount` 的谱，键宽 = 柱子宽 = 轨道宽减间隔（默认 320 的轨道是 280），键深 = 底面长（`length`，默认 240），轨道和底面怎么变键跟着变；无限轨的谱没有间隔，键和轨道一样宽。玩家设置「按键缩放」（0.8–1.3）等于把轨道缩放（14:25「“按键缩放”相当于把轨道进行缩放」「和无轨按键进行缩放」，7.218）：每根柱子的宽绕轨道中线、底面长从前面往后都乘它，键、水雷、浪花的面跟着；无轨键的 240 底面也乘它。轨道的位置、柱子前面（判定面）和平的画面里的判定范围都照谱面；3D 里按到哪根柱子照旧按画出来的柱子算（叠着的地方前面的优先）。放大时相邻的柱子会叠一点，缩小时间隔变大。键在轨道中间，判定照旧按整条轨道；水雷、轨道水雷跟轨道宽。`insert` 和 `delete` 是一个事件（§3），意义同 v4 §3.6、§3.7。写了 `lanes` 就只有写出来的这些轨道（无限轨时中间缺的 id 和画面能露出的轨道照样自动补上）。

**每条轨道是单独的物件，宽度各管各的 `laneWidth`**（Kelvin 2026-11-08 02:39：「默认轨道宽度不变，都是默认6轨的轨道宽度」，7.213；02:48：「现在没有“有限轨”“无限轨”的概念，就是把每个轨道当作单独的object处理」，7.214 起不再有平分画面）：每条轨道用自己的宽度：`width` / 240 × `laneWidth`（再乘全局缩放 `scale`），`width` 默认 240，所以默认轨道就是 `laneWidth` 宽；轨道一条挨一条，整块以中轴（x 960 加镜头平移）为中心。加减轨道、插入删除、哪条轨道变宽变窄，都只是把旁边的轨道推开或收拢，别的轨道宽度不变；整块比画面宽时两边的轨道露在画面外面。键：默认轨道里 240（键占轨道的 240 / `laneWidth`，最多占满），轨道变宽变窄键跟着变，最宽到柱子的宽；间隔照旧 40。`laneWidth` 写 320 时，6 条默认轨道和以前的 6 轨谱一模一样。没写 `laneWidth` 的谱（7.214 以前存的）保持原来的样子：`laneWidth` 取所有轨道都在自己宽度（`width`，插入的轨道算进来）时正好铺满 1920 的值，8 条默认轨道 240、6 条 320、9 条 213.33；轨道宽度不变的谱和以前一样，中途插入、删除轨道或变宽变窄的谱改成推开旁边的轨道（9 条轨道的谱插入轨道 0 之前 8 条是 213.33，插进来以后和以前一样）。存盘时写出这个值。无限轨的谱不看 `laneWidth`（不写）。

**有限轨中间的间隔**（Kelvin 2026-11-07 06:36：「轨道数量默认改回6轨，中间间隔一点」，7.197）：写了 `laneCount` 的谱，每条轨道画成一根柱子，相邻两根之间空 40（乘轨道缩放），6 轨时轨道 320 = 柱子 280 + 间隔 40。轨道线画在柱子两边；判定线每条轨道画一段，间隔里不画。键就是柱子底面那么大（上面）。浪花、潮汐、浪花水雷照旧落在判定线上，画成横跨几条轨道的一整块（06:35：「浪花现在变成spanning多个底面的一个大的东西，中间用虚线链接」）：每条轨道一段，间隔里用虚线连起来，一起落下。只是画法：判定还是按整条轨道，所以按在间隔里算离得近的那条轨道。无限轨的谱没有间隔。

```json
"lines": { "upper": 1060, "lower": 120, "upperEvents": [], "lowerEvents": [], "scale": 0.8, "scaleEvents": [], "camera": 120, "cameraEvents": [] }
```

| 键 | 默认 | v4 里叫 |
|---|---|---|
| `upper`、`upperEvents` | 1080 | `upperJudgementLine`、`upperEvents` |
| `lower`、`lowerEvents` | 120 | `lowerJudgementLine`、`lowerEvents` |
| `scale`、`scaleEvents` | 1 | `laneScale`、`laneScaleEvents`（全局缩放） |
| `camera`、`cameraEvents` | 0 | `cameraFrame`、`cameraFrameEvents`（镜头平移） |
| `upperExtend`、`upperExtendEvents` | 820 | 同名，写在 `judgementLine` 里（柱子伸到天线外面多长） |
| `lowerExtend`、`lowerExtendEvents` | 820 | 同名，写在 `judgementLine` 里（柱子伸到地线外面多长） |

**轨道高度**（Kelvin 2026-11-07 15:58：「也是可以选择轨道高度天线与地线之间的距离，天线外侧延申高度和地键外侧延伸高度」；15:59：「这些全部都是动作类事件，可随时间变化」，7.200）：天线和地线之间的距离就是 `upper − lower`，用 `upperEvents`、`lowerEvents` 改。柱子（§5.6 的 3D 画面）在天线外侧再伸出 `upperExtend`、在地线外侧再伸出 `lowerExtend`（参考坐标单位，默认 820，也就是画到画面外面，和以前一样），最外面 700 慢慢变淡；比 700 短就整段都在变淡，0 就是到线为止，负数当 0。都是运动事件（§3），可以按拍变化。只改画面：判定照旧整列（§5.4），柱子画多长都不影响判定。平的画面（没写 `laneCount`、也没转视角的谱）没有柱子，看不出来。

**轨道是三维里的长方体：原点、下落向量、天地距离**（Kelvin 2026-11-08 23:10：「每一个轨道能设置三维朝向啊，当作一个三维空间内的长方体，类似于海面」；23:42：「轨道本来的外观不要改，然后加一个法向量参数+轨道原点相对于绝对原点的坐标」「把conflicting的东西清理了，其他的都保持不变」；11-09 00:10–00:13 法向量改成下落向量，7.216。代替 7.210 的整列移动 `x`、`y`、`z`）：每条轨道可以写下面这些通道，写法同 §5.8（基础值的键名就是通道名，加 §3 的运动事件 通道名 + `Events`，事件外回到基础值）；不写就是默认值，和以前一样。

位置都从绝对原点 (0, 0, 0) 量：x 从中线（和键的 `x` 一样，乘全局缩放 `scale`，跟着镜头平移），y 从画面正中（参考 y 600）往上，z 从柱子纵深的正中（键的 `z` 120）往里。所以默认的轨道、海面都在原点附近，样子和以前一样。

| 通道 | 默认 | 说明 |
|---|---|---|
| `originX` | 不写 | 轨道正中心的 x。不写就照旧排在横排里；写了就离开横排（别的轨道不再给它留位置），中心在这里。可以挪到别的轨道上面，按在重叠的地方算中心离得近的那条 |
| `originY` | 不写 | 轨道正中心的 y（天线和地线的正中）。不写就在判定线 `upper`、`lower` 的正中，跟着它们的事件动 |
| `originZ` | 0 | 轨道正中心的 z。3D 里整根柱子往里或往外挪，画在看上去的位置（远小近大） |
| `fallX`、`fallY`、`fallZ` | 0、−1、0 | 下落向量：地键下落的方向。只看方向，长度不管，全零当默认；有事件时逐分量插值再取方向 |
| `distance` | 不写 | 天地距离（天线和地线之间）。不写就是 `upper − lower` |
| `scaleY` | 1 | 柱子在天线、地线外面伸出的长度（`upperExtend`、`lowerExtend`）乘这个数；0 或负数就是到线为止 |
| `length` | 240 | 底面长：柱子沿纵深的长度（7.217；宽是轨道的 `width`，见下面）。原点还是长方体的正中：前面在 `originZ` − 长/2，后面在 `originZ` + 长/2。负数当正数 |

* 地线在 原点 + f·d/2，天线在 原点 − f·d/2（f 是下落向量，d 是天地距离）。轨道的朝向是从朝下 (0, −1, 0) 转到 f 的最短旋转，不另外自转：f 正好朝上时绕视线转半圈（倒过来，正面还朝玩家）；f 朝玩家 (0, 0, −1) 时柱子沿纵深躺下，地键朝玩家落过来；f 朝右 (1, 0, 0) 时柱子横过来，地键往右落。外观不变：底面默认是 宽 × 240 的方柱，颜色、伸出判定线的长度照旧。
* **底面**（Kelvin 2026-11-09 05:00：「然后轨道的事件改为“底面事件”，长宽都能改」，7.217）：底面是柱子垂直于下落向量的截面，宽是 `width`（和它的事件），长是 `length`（和 `lengthEvents`）。跟着长变的：3D 里的柱子、这条轨道上的键（含长条和水雷）的立体厚度、判定方框（3D 里点按找柱子用的长方体）、浪花的波浪面和珍珠面；判定线、键和浪花画在柱子的前面，打击特效还在柱子纵深的正中（原点）。全局缩放 `scale` 和 `laneWidth` 只管宽，不缩放长。平的画面里看不出来。
* 整根轨道一起动：这条轨道的那段判定线（线、发光、波纹、刻度）、两边的分隔线、轨道发光、3D 里的柱子、上面的轨道键（小数轨道上的键按两边的轨道插值）、水雷的判定线、打击特效。键在这条轨道自己的天线、地线判定，「离判定线」沿着轨道的方向量；判定和 3D 里的点按也按它挪过、转过的位置。不在某一条轨道上的 `x` 键（含海面上的键）、没写 `spans`（§5）的浪花、潮汐、浪花水雷不跟；残影在它那一刻轨道所在的位置。平的画面（没写 `laneCount` 也没转视角的谱）里纵深和转动不显示，`scaleY` 只有 3D 的柱子看得出来。
* 下落向量朝玩家时，键接近判定线看起来不明显：游戏不另外提示（Kelvin 2026-11-09 00:28 选了「只靠流速」），这些键把流速调高就行（比如天地距离 5000、每拍 2500）。
* **旧谱换算**（7.216 以前的 `x`、`y`、`z`，读的时候换，存盘写新键，位置不变）：`originX` = 0 拍时它在横排里的中心 + `x`（轨道离开横排），`originY` = 判定线 `upper`、`lower` 基础值的正中 − 600 + `y`（判定线有事件时，换算后的轨道不再跟着判定线上下），`originZ` = `z`；事件里的值加同样的数。轨道自己也写了新键的，那一项用新键。

```json
{ "id": 5, "originX": 0, "fallY": 0, "fallZ": -1, "opacity": 0,
  "opacityEvents": [ { "beats": [87, 88], "values": [0, 1] }, { "beats": [88, 88.25], "values": [1, 0] } ] }
```

上面是一条躺下、地键朝玩家落的轨道：87 拍淡入，88 拍的键打完以后 0.25 拍淡出（谱面编辑器的「操作 A」）。

**浪花、潮汐跨轨道和海面 `spans`**（Kelvin 2026-11-09 00:01：「然后海浪可以选择跨过若干个轨道/海面，这些轨道/海面之间用虚线链接」；00:05：「浪花跟海面类似，原来的珍珠线也拓展为珍珠面」，7.216）：

```json
{ "type": "universal", "beat": 32, "spans": [ { "lane": -3 }, { "lane": 1 }, { "lane": 2 }, { "sea": 0 } ] }
```

* 列表里的轨道、海面不用挨着。每条轨道上是一片，盖住这条轨道柱子的宽，在这条轨道自己的判定线上（§4 的原点、下落向量）；每片海面上是一片，宽是这片海面，落在海面上（§5.7）。按列表的顺序，每两片之间画一条虚线，连在两片离得最近的两条边的中点之间；轨道和海面动的时候虚线跟着。不存在的轨道、海面跳过。
* 3D 里每片是一个面：地线的是波浪面（铺满轨道在判定线那里的正方形截面；海面上是它那一段宽、海面的整个深），天线原来的珍珠线变成珍珠面（同样的地方铺满珍珠，间隔 60）。没写 `spans` 的浪花在 3D 里天线的也是珍珠面。
* 还是一个键，几片一起判定，时间不变；关掉全屏判定时按到哪一片都算。潮汐、浪花水雷一样。
* 没写 `spans` 的照以前：按左右范围盖住经过的轨道，间隔处虚线。
* 现在还不行的：浪花带自转（`rotationEvents`）又写了 `spans` 时，3D 里的面不跟着转；平的画面里海面上那一片不跟海面倾斜。

### 5.1 浪花水雷 `tideMine`（2026-10-31）

浪花和潮汐的水雷版本：画成那条线的浪花（地面是波浪、天上是珍珠串，带 `duration` 时后面跟潮汐的长条），颜色是水雷红。键同 `universal`（没有轨道、横移、公转）。不算进音符总数，算进水雷数；碰到时断连击，分数加 10,000（2026-11-01 起，见 CHART_FORMAT_v4 §6.4），自动播放从不碰。

* **浪花水雷**（不写 `duration`）：判定区里任何位置按下就算碰到（键盘上这条线的任何键，空格也算），±133.33 ms，只算按下的那一下。同一条线上它的判定窗和别的音符（所有轨道的 DROP、STREAM 头，还有浪花）重叠时，按普通水雷的规则互扣（v4 §6.4）：水雷让出那个音符的共鸣窗，那个音符的回响窗扣掉水雷窗。
* **潮汐水雷**（写了 `duration`）：像轨道水雷，只是封住整条线的判定区：到线后到结束 `[T, end)`，手指在判定区里（按下、停着、滑进来）或按着这条线的键，每碰一次断一次连击，离开后才会再算。同一条线上共鸣窗碰到它的音符先判，那个音符没有回响；打出共鸣后这条线的潮汐水雷睡 150 ms（v4 §6.4.1 的让位和保护，只是按整条线算）。

### 5.2 DRAG `drag`（2026-11-05；8K 版 2026-11-07）

Kelvin 2026-11-05：「加 Drag，手指在对应判定线就判」「手指提前放着或者滑过去都算，到点时手指在那儿就是共鸣，不在就是迷失，没有回响」；2026-11-07 游戏退回 8K 定轨可变轨版本时留下，同一天「drag还是无轨的状态」：不放在轨道上，用自己的横坐标（7.191）。2026-11-08 02:51 改成「也上轨道」（Drag 和水滴一样属于某条轨道、跟着轨道动；只有放到海面上才按横坐标，7.214）。

```json
{ "type": "drag", "lane": 2, "beat": 48 },
{ "type": "drag", "line": "upper", "lane": 1.5, "beat": 50 },
{ "type": "drag", "on": 0, "x": 360, "beat": 52, "xEvents": [ { "beats": [50, 52], "values": [-600, 360] } ] }
```

* **在轨道上**（写 `lane`，可以是小数，§5.3）：和 DROP 一样属于这条轨道：在轨道中间，跟着轨道插入、删除、变宽变窄、原点和下落向量（§4），宽 = 这条轨道的键宽；`offsetX`、`offsetXEvents` 和轨道键一样只挪画面。判定也按这条轨道：手指离轨道中心不超过 0.8 个轨道宽（轨道的一半再加两边各 30%），不管多高；全屏段落里任何手指都接得住（和点键一样，§5.4）。轨道 id 不存在时像 DROP 一样自动加上。轨道水雷按它的轨道让它。
* **用自己的横坐标**（写 `x`、不写 `lane`：海面上的 DRAG，和 7.214 以前的谱；`lane` 和 `x` 都没写就是 `x` 0）：下面几条说的就是这种。
* 位置：`x` 是横坐标，从屏幕中线量起（中线在 −1 和 1 两条轨道中间，单位和 1920 宽的画面一样，8 条默认轨道的中心是 ±120、±360、±600、±840），没写就是 0。`xEvents` 让它左右移动，写法和其他事件一样（`beats`、`values`、`ease`）：在某个事件里用这个事件的值，事件外面回到 `x`。判定线的镜头和轨道缩放对它和对轨道一样（跟着平移、缩放）；轨道插入、删除、变宽变窄都不挪它。写了 `lane`、`offsetX`、`offsetXEvents` 都忽略，不会因此加轨道。
* 宽一个标准轨道宽（240，乘轨道缩放）。移动、旋转、自转、公转、透明度、残影、故障、扭曲、`fake` 照常（这些只改画面，判定只看 `x` 和 `xEvents`）。`duration`、`height` 写了也忽略。
* 不用按，只看手指在不在：从判定拍前 133.33 ms 到判定窗结束（判定拍后 133.33 ms），任何一根按着的手指（在漩涡里按下的不算）不管多高（2026-11-07 起整列判定，§5.4；以前要在这条线的判定区里）、离它当时的横坐标不超过 0.8 个它的宽（宽的一半再加两边各 30%，和点键时够得着旁边的轨道一样远），就接住这个 DRAG；电脑上按着这条线的某个键，那条轨道开着、中心离它不超过 0.8 个它的宽，也接住。每个触摸事件和每一帧都看：手指提前停在那里、滑过去、按下去，或者它滑到手指下面，都算。
  * 判定拍之前接住：到判定拍时判共鸣。
  * 判定拍或之后接住：马上判共鸣。
  * 一直没接住：判定窗结束时迷失。没有回响。
* 按着长条的手指、正在点别的键的手指也能接住；接住不占用手指，也不挡别的键。同一拍的浪花不和它联合判定（浪花照旧要点）。
* 计分：算一个音符（音符数、连击、共鸣链都算）；Δt 记 0，算一个 PERFECT（±33 ms 以内），不进早晚统计。自动播放到判定拍判共鸣。

### 5.3 小数轨道、`x` 键和无轨时间（2026-11-07，7.192）

Kelvin 2026-11-07 04:02：「定轨状态支持小数轨道，然后加一个无轨时间和有轨时间。有轨时间默认6轨。无轨时间内横向拖动精确到5px。」


* **小数轨道**：`tap`、`hold`、`mine`（含轨道水雷）的 `lane` 可以是小数，放在相邻的两条轨道 L < R（按 id）之间：`f = (lane − L) / (R − L)`，前一半从 L 的中心走到 L、R 的分界线，后一半从分界线走到 R 的中心。1.5 在 1、2 号轨的分界线上，1.25 在 1 号轨中心右边四分之一条轨道处。没有 0 号轨时 `"lane": 0` 是 −1、1 号轨的分界线，也就是屏幕中线（以前这样的键读取时丢掉）。最外面那条轨道的外面按它的宽往外延。宽度按 `f` 在两条轨道的宽之间取。轨道变宽、插入、删除、缩放、镜头平移时跟着走。离整数不到 0.0001 的就是那条轨道；写了谱里没有的整数轨道照旧自动加上，小数不加轨道。
* **`x` 键**：`tap`、`hold`、`mine`（含轨道水雷）不写 `lane`、写 `x`（和 `xEvents`）时，像 DRAG 一样用自己的横坐标（§5.2 的写法：从屏幕中线量起，跟着镜头和轨道缩放，不跟任何轨道），宽一个标准轨道（240，乘轨道缩放）。`lane` 和 `x` 都写了就用 `lane`。

* **无轨时间** `laneless`（顶层）：`[{"from": 开始拍, "to": 结束拍}]`。这段时间轨道线、轨道底色和判定线上的轨道提示淡出：每段开始前后各 1/4 拍从有到无，结束前后各 1/4 拍从无到有（两段靠得太近时淡不到底）。只是不画：轨道照样存在（插入、删除、变宽照常），所有键照常判定。不写 `from` 是从头开始，不写 `to` 是到最后；重叠或相接的几段合并成一段。谱面编辑器在无轨时间里放 `x` 键，横向按 5 吸附。
* 不写 `lanes` 的谱仍是 8 条默认轨道；6 轨是谱面编辑器新建谱的默认值（§2）。

海面和轨道（§4）是同一种物件（Kelvin 2026-11-08 23:10「当作一个三维空间内的长方体，类似于海面」；11-09 00:08「海面中心也默认为（0，0，0）。默认法向量朝上」，00:13 改成下落向量，7.216）：一片和下落向量垂直的面，键顺着下落向量落在上面。位置的量法同 §4（x 从中线、y 从画面正中往上、z 从柱子纵深的正中往里）。

| 键 | 默认 | 说明 |
|---|---|---|
| `originX`、`originY`、`originZ` | 0、0、0 | 海面正中心。x 和键的 `x` 一样从中线量（参考坐标单位，跟着轨道缩放和镜头平移）；y 0 是参考 y 600（地线默认 120，天线默认 1080）；z 0 是柱子纵深的正中 |

| `width` | 1920 | 沿着海面横向的宽，以原点为中心 |
| `depth` | 240 | 沿着海面纵深方向的深，以原点为中心（默认和柱子一样深） |
| `from`、`to` | 一直显示 | 显示的拍数范围，开头半拍淡入、最后半拍淡出 |
| 上面各键 + `Events` | 没有 | 都是运动事件（§3），事件以外的时间回到上面的值 |

**旧谱换算**（7.216 以前的键，读的时候换，存盘写新键，样子不变）：`x0`、`x1`（默认 −960、960）→ `originX` 是两端的正中、`width` 是 x1 − x0；`y`（默认 600）→ `originY` = y − 600；`z0`、`z1`（默认 0、240）→ `originZ` 是两端的正中 − 120、`depth` 是 z1 − z0；`tilt`（度，正数右端高）→ 下落向量 (sin tilt, −cos tilt, 0)，就是从朝下绕视线转 tilt。事件跟着换（一对端点里只有一个有事件，或两个的事件拍子对得上时逐个换算；`tilt` 的事件换成下落向量在事件两端的值，中间按分量插值，转得多的事件中间的角度和以前略有不同）。海面自己也写了新键的，那一项用新键。

* **落在海面上**：音符写 `"on": 海面序号`（`seas` 里的第几个，从 0 数）就落在那片海面上。海面不属于任何轨道，所以海面上的键是无轨键：写 `x`、不写 `lane`（§5.3 的 `x` 键；DRAG 也一样），落点是海面在这个键的 x 处的高度，键跟着海面倾斜；写了 `lane` 的键（小数轨道也一样）`on` 不算，照旧落在判定线上，存盘时也不写出。浪花、潮汐、浪花水雷落在海面在画面里那一段的正中，只画在海面的左右两端之间，跟着倾斜，打中时光带沿着海面升起（潮汐按住时的水位和细光带还在它的判定线上）。3D 里海面上的键快落下时，落点在海面上按键的颜色渐渐显出来（2026-11-08）。序号不存在就当没写。没写 `on` 的照旧落在判定线上。
* **判定**：海面自己不判定、不回收、不算音符，也不挡判定，按在海面上照常判定。海面上的键和别的 `x` 键一样按自己的横坐标判定（§5.3）：以它的 x 为中心、它的宽（240，乘轨道缩放）的一条竖带，任何高度按下都算（整列 §5.4）；附近没有更近的键时 0.8 个宽也算；全屏段（§5.5）里照全屏。3D 视角里每个键按它自己的纵深判定（2026-11-08，7.215；Kelvin 19:43「我目前的这些出现都要能靠垂直判定判定到」）：取从眼睛穿过手指的那条线在这个键的 `z`（§5.8，含运动）处的 x，所以竖带就是键落下的位置那一竖列，任何高度都算，近的远的都一样。2026-11-08 19:37 起这些范围都放宽到 3 倍（`GameEngine.SEA_REACH`，Kelvin「极大放宽判定范围试一下」；海面上的水雷不放宽）。浪花、潮汐照旧，时间也不变。
* **样子**：深蓝色 #1F4FD8 半透明的一整片，前缘 #7FA6FF。一整片穿过柱子之间的间隔，不按轨道切开，也不画虚线。3D 视角里是有纵深的一片，表面二维起伏：h = 7·sin(2πx/280 − 2t) + 7·sin(2πz/260 − 1.4t + 0.004x)（x、z 是参考坐标单位，t 是歌曲的秒数）；3D 里普通浪花的薄片也照这样起伏（每块按自己的 x、z）。平的画面（没写 `laneCount` 也没转视角的谱）里是一条倾斜、起伏的深蓝粗线；平的画面里浪花还是原来的正弦线。
* **限制**：海面在柱子正面前面的部分（纵深在柱子正面之前）画在平面画面的下面，键和判定线会盖住它。
* 谱面编辑器的工作文本（旧格式）也认 `seas` 和 `on`，事件写成旧格式的样子。

### 5.8 三维运动（2026-11-07，7.209）

Kelvin 22:54（谱面编辑器的运动编辑设计页）：「“指数”改为“缓动”，其他的都可以」。`tap`、`hold`、`mine`、`drag`（轨道键和 `x` 键都一样）可以写下面五个通道，每个是一个基础值（键名就是通道名）加 §3 的运动事件（通道名 + `Events`），事件外回到基础值；不写就是默认值，和以前一样。`universal`、`tideMine` 写了忽略，不写回。

| 通道 | 默认 | 说明 |
|---|---|---|
| `z` | 0 | 纵深，单位同海面的 `z0`、`z1`（0 是柱子正面，往里为正，负数往外）。3D 里键画在这个纵深看上去的位置（远小近大），方块也往里挪；平的画面里不显示 |
| `rotationX` | 0 | 绕键自己的横轴转（度；`rotationEvents` 是绕屏幕法线转）。平的画面里像翻牌，键头厚度乘 \|cos\|；3D 里方块真的转，绕键头正面的中心 |
| `rotationY` | 0 | 绕键自己的竖轴（沿着下落方向）转，宽度乘 \|cos\|，尾巴跟着变窄；其他同上 |
| `scaleX` | 1 | 画出来的宽度倍数（键头和尾巴） |
| `scaleY` | 1 | 画出来的键头厚度倍数（尾巴长度还是 `heightEvents`） |

```json
{ "type": "tap", "lane": 1, "beat": 20, "z": 120, "zEvents": [ { "beats": [16, 20], "values": [240, 0] } ],
  "rotationYEvents": [ { "beats": [18, 20], "values": [0, 180] } ], "scaleX": 1.5 }
```

### 5.9 跟空间的键 `"track": "space"`（2026-11-09，7.216）

Kelvin 2026-11-08 23:20：「按键的轨迹可以选择跟所在海面/判定线绑定或者跟着绝对空间坐标绑定」。`tap`、`hold`、`mine`、`drag` 写 `"track": "space"` 就跟空间；没写的照旧跟所在的轨道或海面（以前的谱全是这样）。

* **写了 `positionEvents` 的**：轨迹直接是绝对坐标，和 §4 的原点同一套：`positionEvents` 的值是从画面正中往上的 y（天线、地线的键都一样），横坐标是 `offsetX` / `offsetXEvents`（海面上的键、`x` 键是自己的 `x`）从中线量，纵深是 §5.8 的 `z`（0 和没挪过的轨道上的键一样深）。轨道、海面、判定线的事件（判定线抖动）、横排推开、全局缩放 `scale` 都不带着它动，只跟视角（`view`、镜头平移）。
* **没写 `positionEvents` 的**：按它判定那一拍轨道的样子（位置、宽、上下、纵深、下落向量）冻住，照那一刻的轨道正常下落；之后轨道再怎么动它都不跟。
* **判定**照样按时间，按它所在轨道的天线或地线；打击特效、关掉全屏判定时的落点，都用它在判定那一拍自己的位置。
* 现在还不行的：浪花、潮汐、浪花水雷不能跟空间（写了忽略）；海面上的键、`x` 键跟空间但没写 `positionEvents` 时，照旧跟着海面或自己的 `x` 动，不冻住。

```json
{ "type": "tap", "lane": 2, "beat": 40, "track": "space", "offsetX": -300,
  "positionEvents": [ { "beats": [38, 40], "values": [500, -480] } ] }
```

上面的键从画面正中往上 500、中线左边 300 落到 −480（地线默认 120 = 画面正中往下 480），在轨道 2 的地线判定。

## 6. 漩涡 `veils`

```json
"veils": [
  { "shape": "circle", "radius": 210, "x": 1480, "y": 322, "from": 112, "to": 130,
    "opacityEvents": [ { "beats": [112, 113], "values": [0, 1] } ] }
]
```

键：`shape`（`circle` / `polygon`）、`radius` 或 `points`（`[[x, y], …]`）、`x`（默认 960）、`y`（默认 600）、`rotation`（0）、`opacity`（1）、`from` / `to`（显示的拍数范围，v4 的 `startTime` / `endTime`，不写就是不限）、`xEvents`、`yEvents`、`rotationEvents`、`opacityEvents`、`glitches`、`distortions`。规则同 v4 §6.10。

三维运动（2026-11-07，7.209）：同 §5.8 的五个通道 `z`、`rotationX`、`rotationY`、`scaleX`、`scaleY`（和它们的事件），都绕漩涡的中心；再加 `pointEvents`：`[{"i": 0, "xEvents": […], "yEvents": […], "zEvents": […]}]`，第 `i` 个顶点（从 0 数）的移动，加在 `points[i]` 上（参考单位；`z` 加在漩涡的 `z` 上）。没有这个顶点的项读入时丢掉并修正。大小、转动（翻牌，按 |cos| 变窄）和顶点的移动都跟着挡判定，画多大挡多大；纵深只改画面（3D 里画在看上去的位置，每个顶点按自己的纵深）。

### 6.1 水帘 `curtains`

```json
"curtains": [
  { "shape": "polygon", "points": [[-300, -560], [300, -560], [300, 560], [-300, 560]], "x": 1260,
    "from": 64, "to": 96, "blur": 24, "blurEvents": [ { "beats": [64, 66], "values": [0, 24] } ] }
]
```

纯演出：把盖住的画面整个模糊（轨道、音符、漩涡、判定线、打击特效、连击数、判定字、四角的分数和暂停键都一样），只有暂停菜单不受影响；从不判定，点在上面照常判定。键同 `veils`（`distortions` 让边缘摆动，`glitches` 不画），另加 `blur`（模糊半径，参考坐标单位，默认 16，0–64，超出范围读入时修正）和 `blurEvents`（按拍变化，同其他事件）。水帘盖在屏幕上，三维运动里的纵深（`z`、顶点的 `z`）不起作用，其他的同漩涡。边缘柔和，里面有细细的水痕往下流，颜色偏冷一点；中心和形状都跟漩涡一样随屏幕比例拉伸（横向乘 屏幕宽 / 1920、纵向乘 屏幕高 / 1200）。

## 9. 谱面版本 2.0：格式 v7「简单函数」（2026-11-09，7.220）

Kelvin 2026-11-09 18:44（谱面编辑器串）：「定义下面所有的1维函数R->R都由简单函数组成。每个简单函数包含以下几个变量：1）起点x_i 2）终点x_f 3）起始时间t_i 4）终止时间t_f 5）缓动指数e」，接着定义了轨道、各种键、水幕 / 水帘和相机，「其他所有的全部删掉。海面先不要了，太复杂了」；18:45：「只保留垂直判定，全屏判定也可以先删了」。

```json
{ "format": 7, "charter": "Kelvin", "constant": 12.5,
  "lanes": [
    { "id": 1, "v": { "x": -120 }, "S": [ { "ti": 8, "tf": 10, "xi": 480, "xf": 360, "e": 2 } ] },
    { "id": 2, "v": { "x": 120 }, "a": { "w": [ { "ti": 0, "tf": 4, "xi": 0, "xf": 240 } ] } }
  ],
  "keys": [
    { "type": "tap", "lane": 1, "h": [ { "ti": 30, "tf": 32, "xi": 1080, "xf": 0 } ] },
    { "type": "tide", "lanes": [1, 2], "face": "sky", "h": [ { "ti": 34, "tf": 36, "xi": 1080, "xf": 0 } ],
      "H": [ { "ti": 36, "tf": 38, "xi": 1080, "xf": 0 } ] }
  ],
  "volumes": [ { "kind": "veil", "shape": "ellipsoid", "V": { "w": 600, "h": 300, "d": 240 }, "p": { "y": 200 },
                 "o": { "x": [ { "ti": 40, "tf": 48, "xi": 0, "xf": 0.6 } ] } } ],
  "camera": { "P": { "x": 0, "y": 1000, "z": -6000 }, "fov": [ { "ti": 84, "tf": 86, "xi": 60, "xf": 11 } ] } }
```

`editor` 是谱面编辑器自己的数据，游戏不读。

* **简单函数** `{"ti", "tf", "xi", "xf", "e"}`：开始拍、结束拍、起点、终点、缓动指数（1 不写）。段内是 `xi + (xf − xi)·p^e`，`p = (t − ti) / (tf − ti)`；`tf = ti` 时从 `ti` 起就是 `xf`。一个函数写成一个数（常数）或一串段（按 `ti` 排，重叠时后开始的从它的 `ti` 起算）。段外**保持**：第一段之前是它的 `xi`，两段之间是前一段的 `xf`，最后一段之后是它的 `xf`（旧格式的事件外回到基础值，v7 不是）。没有自定义曲线。默认值不写。
* **轨道** `lanes`：
  * `u` 下落向量（用时归一化，零向量当默认 (0, −1, 0)）；`v` 原点（x 离中线往右、y 离画面正中往上、z 往里，参考单位）；`a.w` 宽、`a.h` 底面长（默认都是 240）；`S`、`F` 天面和底面在轨道向上的轴（−u）上离原点多远（默认 480、−480，就是判定线 1080 / 120）；`s`、`f` 柱子越过天面、底面往外淡出的长度（默认 820）；`o` 不透明度（默认 1，用的时候限在 0–1；Kelvin 21:37「加回透明度」，7.223）：轨道画的所有东西（柱子、天面底面、边、判定线段和它们的光）和轨道上的键都乘它，0 就全都不画，判定不变。`v.x` 总是写出来。
  * 游戏每一帧按这些函数摆柱子（`LaneLayout.pose7`）。没有间隔、插入 / 删除、全局缩放：轨道的出现和消失靠它的函数（比如 `a.w` 从 0 长出来，或 `o` 从 0 淡入）。每条轨道单独成一个物件，判定线和浪花按轨道分开画（`LaneLayout.separate`）。
* **键** `keys`：
  * `tap`、`drag`、`mine` 只有 `h`；`stream`、`streamMine`（轨道水雷）有 `h`、`H`；`wave`、`waveMine`（浪花、浪花水雷）有 `h`、`lanes`；`tide`、`tideMine`（潮汐、潮汐水雷）有 `h`、`H`、`lanes`。天键写 `"face": "sky"`，地键不写。
  * `o` 不透明度（默认 1，限在 0–1，7.223）：画出来的不透明度是键的 `o` 乘它那条轨道的 `o`（浪花、潮汐取它跨的轨道里最大的）；0 不画，判定不变。
  * `h` 是离它那一面多远：地键在 `F + h`，天键在 `S − h`。键从 `h` 第一段的 `ti` 起出现（之前不出现），在最后一段的 `tf` 判定（那时 `h` 应该是 0）。放在第 T 拍的键默认是一段 T − 2 → T、1080 → 0。
  * `H` 是物件沿柱子的高：长条从判定起，到 `H` 最后一段结束为止（那时降到 0）；没写 `H` 的长条长 1/64 拍。
  * `lanes` 是浪花、潮汐跨的轨道 id；一条都不在了就跨整个场地。
  * `"fake": true` 是假键（Kelvin 2026-11-09 20:37「假键的逻辑倒是可以保留」，没写就是真键）：规则同 §5 的 `fake`，照常画，到判定拍（水流、潮汐到结束）就不再画；不判定、不计分、不算连击和多押。浪花水雷、潮汐水雷不能是假键（写了忽略）。
  * `trails`、`glitches`、`distortions`（7.228，Kelvin 2026-11-10 02:17「故障效果和残影要加上啊，还有那个distortion，这些还是保留」）：残影、故障、扭曲，写法和 §5 的同名键一样（`from` / `to` 是拍），没写就没有。残影的每个副本画在它那一刻键的位置和它轨道那一刻的样子上：键跟着轨道动（比如绑定轨道上横飞的键），残影就留在它走过的地方。
  * 读的时候没有 `h` 段的键、轨道 id 不存在的键丢掉；文件里键的顺序随意。
* **水幕 / 水帘** `volumes`：`kind` 是 `veil`（水幕，挡住判定）或 `curtain`（水帘，模糊），`shape` 是 `box` 或 `ellipsoid`，`V` 是大小（`w`、`h`、`d`，默认 480），`p` 是中心（默认原点），`o` 是它自己的 z 轴朝哪边（默认 (0, 0, 1)，往里；Kelvin 21:21「加一个z轴朝向吧，也是三维变量」）。`V` 的 `d` 沿 `o`，`w`、`h` 是从 +z 最短地转到 `o` 时 x、y 轴转到的方向（`o` 正好朝外 (0, 0, −1) 时绕竖轴转半圈）；`o` 用时归一化，零向量当默认。`w` 或 `h` 不大于 0 的时候不出现。不写 `o` 就是默认。水帘还有 `b`：模糊强度（参考单位，默认 16，用的时候限在 0–64；水幕不用）。`distortions`（扭曲，水幕的水纹和水帘的边缘摆动有多强，没有段的时候是 1）和水幕的 `glitches`（故障）写法同 §6 漩涡的同名键（7.228）。
  * 游戏里（7.222，Kelvin 21:21「椭球和长方体可以」）：每一帧按相机算出它在屏幕上的外形，椭球是精确的椭圆，长方体是 8 个角的凸包，穿过相机近处的部分切掉，相机在它里面时就是整个屏幕。水幕在外形里画原来的水纹（椭球是同心圆、长方体是光网，随外形拉伸），再画长方体的 12 条棱、椭球沿自己 z 轴的 5 圈光圈；手指按下的点在水幕的外形里（视线穿过水幕）就不判定，抬起前都无效。水帘只把外形里的东西模糊（按 `b`），不画边、不挡判定。没有不透明度事件。
* **相机** `camera`：位置 `P` 和视角 `fov`，总是看着原点 (0, 0, 0)，+y 朝上（正上方、正下方时 +z 朝上）。默认 P = (0, 0, −6351.24)：1200 高的画面正好填满柱子前面（原点前半个柱子深，120）处的 11° 视野（`Chart7.CAMERA_DIST`）。
  * `fov`（7.224，Kelvin 2026-11-09 22:28 在写谱串卡片上选「加视角」）：上下方向的视角（度），一个简单函数，默认 11（不写），用的时候限在 1–150。画面和按下的视线都按它算，HUD 不变；近平面照旧是到原点距离的 0.05 倍左右。旧谱换成 v7 没有 `fov`（都是 11）。
* **判定**：只有垂直判定（整列，同 §5.4）。没有全屏判定、无轨时间、海面、`x` 键、旋转、视角事件（v4 那种转动、距离的事件；镜头只有 `P` 和 `fov`）。
* 代码：读写 `elements/ChartFormatV7`（模型 `Chart7`、`Lane7`、`Key7`、`Volume7`、`Fn`、`Seg`）；变成游戏用的谱面 `elements/ChartV7Runtime`；旧谱换成 v7 `elements/ChartV7Convert`。

### 9.1 旧谱怎么换成 v7

游戏读到 v5、v6 或更旧的文件时，先按原来的规则读进来，再换成 v7 播放；文件本身不变（谱面编辑器存盘时才写成 v7）。

* 轨道：把判定线、判定线事件、延伸、全局缩放、画面平移、插入 / 删除、轨道运动合起来，在每一拍采样，拟合成简单函数（误差在 0.25 参考单位以内）：`v`、`a`、`S`、`F`、`s`、`f`、`u`。插入 / 删除变成 `a.w` 从 0 长出来 / 缩到 0。
* 键：运动事件 → `h`（每个事件从它开始到下一个开始、它自己结束或判定为止；截掉结尾的缓动不变，截掉开头的按两半拟合）；判定前不透明度低于 0.05 的时候（每 1/64 拍看一次）停在 2000 藏起来；高度事件和长度 → `H`；`x` 键放到判定那一拍离它最近的轨道；浪花、潮汐保留跨的轨道，没有的跨所有轨道；假键还是假键（`fake`）。
* 视角事件 → 相机 `P`（采样拟合），视角大小不要了。
* 漩涡 / 水帘：圆 → 椭球，多边形 → 外框那么大的长方体（不转）；纵深照旧（v7 的原点在柱子一半深处，所以 `p.z` 是原来的 `z` 减 120）；水帘的 `blur` 和 `blurEvents` → `b`（出现之前、消失以后保持）。海面丢掉。
* 键的残影、故障、扭曲，漩涡的扭曲、故障，水帘的扭曲照留（7.228）。
* 其他（旋转、半透明、无轨时间、全屏判定……）就没有了。
* 开发用：JVM 加 `-Dkk.oldCharts=true` 时旧谱照原来的样子播放，用来对比。
